# /autofix — автономный багфикс-луп

Self-verification агентный цикл: даю условие «зелено» → сам итерирую (репро → фикс → проверка → правка) **без промта на каждый шаг**, пока гейты не пройдут. Отличие от соседей:
- `/build-fix` — чинит **уже падающую** сборку/тесты. `/autofix` — берёт **описание бага**, сам пишет репро и чинит корень.
- `/verify` — разовая проверка перед коммитом. `/autofix` — луп до зелёного.

**Баг:** $ARGUMENTS

## Оракул «зелено» (сигнал, на котором держится автономность)
Собери условие из применимых гейтов (только релевантные diff'у):
- `docker compose exec backend pytest tests/ -x --tb=short -q` — **репро-тест проходит + не сломаны соседние**
- если менялся `backend/services/**` или `backend/models/**`: `docker compose exec backend mypy backend/services backend/models`
- `bash scripts/check_conventions.sh`
- если менялся `frontend-react/**`: tsc в контейнере (node на хосте НЕТ) — one-off контейнер с node_modules-volume, либо делегируй `test-runner`

Прогоны гейтов можно делегировать агенту `test-runner` (haiku) — простыня логов не съедает контекст лупа; сложное падение — агенту `debugger` (sonnet).

> ⚠ **Нет docker/гейта → нет автономности.** Если проверку прогнать нельзя (docker down) — НЕ продолжай вслепую и НЕ выдавай «готово». Остановись и скажи юзеру: запусти `make dev`.

## Луп
1. **Репро.** Воспроизведи баг **падающим тестом** в `tests/` (iron rule «падающий тест первым»). Убедись, что он красный по той причине, что в описании. Если баг чисто-визуальный и тестом не ловится — скажи об этом и предложи ручную проверку (UI юзер смотрит сам).
2. **Корень, не симптом.** Прочитай окружающий код, найди корневую причину, сделай **минимальный** фикс. Соблюдай iron rules (`project_id`, `is_deleted`/`soft_delete`, `utcnow`, `Numeric`, `:param`, `invalidate_cache`, логика в `services/`).
3. **Проверка.** Прогони оракул. Long-running (pytest/mypy/build) — через `Monitor` tool: первая ошибка ловится сразу.
4. **Итерируй.** Красное → читай вывод → правь → снова. **Репро-тест не ослаблять** (не подгонять тест под код — это обнуляет смысл оракула).
5. Зелёное по всем применимым гейтам → стоп.

## Стоп-условия (остановиться, спросить юзера — не долбить вслепую)
- Зелено по всем гейтам ✅ (успех).
- **Та же ошибка после 2 попыток** → не повторяй третий раз: переформулируй гипотезу, выведи что узнал, спроси юзера.
- Фикс плодит больше ошибок, чем чинит.
- Нужны архитектурные изменения / смена схемы БД / новая зависимость.
- Достигнут лимит ~12 ходов.
- Требуется бизнес-контекст (какие поля user-facing, можно ли трогать данные).

## Гейты-границы (никогда автономно)
Коммит, push, деплой, миграции с потерей данных, необратимые операции — **только после** того, как юзер посмотрел. `/autofix` доводит до зелёного и останавливается.

## Итог
```
AUTOFIX
  Баг:        <симптом>
  Корень:     <причина в file:line>
  Фикс:       <что изменено, минимальный diff>
  Репро-тест: tests/<...> (теперь стережёт регресс)
  Гейты:      pytest ✓ | mypy ✓/SKIP | conventions ✓ | tsc ✓/SKIP
  Ходов:      N
  → дальше:   /review, затем /ship (пуш — по твоему слову)
```
После зелёного — прогони `/review` (фан-аут) для свежего взгляда. Если трогал `backend/**` — затем `/learn`.
