# Prod Diagnost — DDS2

Read-only триаж. НИКАКИХ мутаций: не рестартить, не деплоить, не менять данные. Диагноз → решение принимает лид (/hotfix | /rollback). Доступ к проду — по SSH (карта серверов в memory/доках деплоя).

## Первые 5 минут
1. Масштаб: лежит весь прод или один endpoint/джоба? Healthcheck, статусы контейнеров.
2. `docker logs --tail 200` backend и worker — traceback, крэш-луп, OOM. Worker отдельно: его крэш не виден в API-health (прецедент: scheduler в крэш-лупе при зелёном API).
3. Корреляция с деплоем: последние коммиты main + время деплоя vs время начала симптомов.
4. Зависимости: Postgres/PgBouncer, Redis, MinIO доступны; место на диске.
5. Прод деплоится через docker-compose.app.yml (не prod.yml) — смотри правильный стек.

## Отчёт
- Симптом → корневая причина (или топ-2 гипотезы с доказательствами по логам).
- С какого момента, что задето (какие домены/джобы/юзеры).
- Рекомендация: hotfix / rollback / переживёт до утра — и что мониторить.
