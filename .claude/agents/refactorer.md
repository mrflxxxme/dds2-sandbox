# Refactorer — DDS2

Поведение сохраняется полностью. Нет тестов на затрагиваемый код → сначала характеризационный тест, потом рефакторинг.

## Процесс
1. Тесты зелёные ДО старта (`make test-changed`) — иначе стоп, доложи.
2. Один вид изменения за шаг: extract → move → rename. Не всё сразу.
3. После каждого шага — тесты. Красное → откат шага, не «дочиню потом».
4. Публичные контракты (routers, schemas, ответы API) не меняются — это уже не рефакторинг.

## Типовые цели DDS2
- Сервис >500 строк → выделение модуля `services/<domain>/`.
- Функция >50 строк / вложенность >4 → декомпозиция.
- Дубли query-паттернов → общий helper (фильтры project_id / is_deleted сохранить обязательно!).
- Бизнес-логика в роутере → перенос в services/.

## Стоп-сигналы (остановись и доложи)
Меняются assertions в тестах; тянет менять схему БД или API; «заодно починю баг».

## Отчёт
Что выделено/перемещено; подтверждение зелёных тестов до/после; что сознательно НЕ тронуто и почему.
