# DDS Learnings (накопленные решения)

> Грузится только при работе с кодом / миграциями / тестами / CI. Для docs/markdown сессий не загружается — экономия context.

## Ошибки и решения
- Alembic "multiple heads": `alembic merge heads -m "merge"` затем `alembic upgrade head`
- FastAPI 422: отсутствует Pydantic валидатор, проверь типы полей схемы
- Next.js hydration mismatch: убедись что сервер и клиент рендерят одинаковое начальное состояние
- Docker "port already in use": `docker compose down` затем `lsof -i :8000`
- PgBouncer prepared statements: `prepared_statement_cache_size=0`, используй `DATABASE_URL_SYNC` для Alembic
- Redis ConnectionError: проверь `REDIS_URL` в .env и что redis контейнер запущен
- ilike injection (P4): ВСЕГДА экранируй `%` и `_` в пользовательском вводе для ILIKE
- Case-sensitive JOINs (P26): коды WB могут отличаться регистром — нормализуй перед JOIN
- **`a || null` vs `a ?? null` для API body**: `|| null` теряет `[]`/`0`/`''` (они falsy), тело запроса превращается в `undefined` из-за `body ? JSON.stringify(body) : undefined` в client.ts. Использовать `?? null` если хотим различать «не передали» и «передали пустое». Прецедент: `warehouse.acceptReceipt` (коммит 600b133)
- **URL-билдинг в API-модуле**: ВСЕГДА `URLSearchParams`, НИКОГДА template literals. `brand = "H&M"` ломает query если через `${brand}` — `&` интерпретируется как разделитель. Учти: URLSearchParams кодирует пробел как `+`, не `%20` (тесты писать под `+`). Прецедент: `reports.getOpiu/getWbBdr/getOrderGeography` (коммит 45dda1d)
- **`process.env` вне функций** — читать env на module level (`const API_URL = process.env.X || ''`), не внутри каждого вызова: тестируемость (mock env один раз) + консистентность с `client.ts`. Прецедент: `supply-chain.downloadVehicleDocument` (коммит 8eaf627)
- **DOMPurify вместо regex-allowlist** для санитизации HTML из AI: ручной regex НЕ ловит `<img onerror>`, `javascript:` в href, `<svg onload>`. Использовать `sanitizeAIHtml()` из `@/lib/sanitize`, hook `afterSanitizeAttributes` для force `target=_blank rel=noopener`. Прецедент: ai-chat + tma/chat (коммит 8c1d167)

## Паттерны которые работают
- Новый API endpoint: schema → service → router → test (в этом порядке)
- Новая страница: скопируй ближайшую существующую, модифицируй
- DB миграция: тестируй `upgrade head && downgrade -1 && upgrade head`
- Кэш: после мутации вызывай `invalidate_cache(prefix)` — суффикс `:*` добавляется автоматически
- Отчёты с датами (P25): привязывай rolling period к дате запроса, не к "сегодня"
- **Pending-файл паттерн** (`.claude/.pending-learn.log`): post-hook пишет, отдельный потребитель читает/чистит. Развязывает синхронные хуки от асинхронной обработки, не порождает рекурсию параллельных claude-процессов
- **`git blame --porcelain -L line,line -- file | awk '/^author-time/ {print $2; exit}'`** — для получения timestamp когда строка добавлена. Быстрее и стабильнее в CI чем `git log -L`
- **Anthropic prompt caching** — `system` как `[{"type":"text","text":...,"cache_control":{"type":"ephemeral"}}]` + `cache_control` на последнем tool. ~90% экономия токенов на повторных вызовах в 5-мин TTL. Backward-compat через kwarg `enable_cache=True` default
- **Idempotent GH issue management** в sentinels — `listForRepo` с лейблом → если есть открытый issue с тем же префиксом title → `update` вместо `create`. Auto-close с комментом «passing again» при восстановлении
- **Opt-in feature через env флаг** (`DDS_PREWARM_ENABLED=1`) — позволяет постепенный rollout инфраструктурных фич, безопасно тестить на одном окружении
- **Anti-recursion через child env** (`DDS_X_ACTIVE=1`) — родительский процесс ставит флаг для child, child проверяет в начале и выходит, чтобы не self-trigger
- **Conditional `claude_args` через GitHub Actions expression** — `${{ contains(labels.*.name, 'security') && '--model opus' || '--model sonnet' }}` для динамического model routing по лейблам PR
- **Wait-on-workflow через GH API polling** — `gh api "repos/X/actions/runs?head_sha=$SHA" --jq '...workflow_runs[] | select(.name=="Y") | .[0].status + ":" + .conclusion'` в loop с timeout. Для post-merge workflow который должен дождаться cd-production. Лучше hardcoded `sleep N`
- **User input через ENV вместо string interpolation в shell** — `PROMPT_TEMPLATE="...\"$USER_INPUT\"..."` уязвим к `$(cmd)` substitution. Вместо: `MY_ENV_VAR="$USER_INPUT" command "$STATIC_TEMPLATE"` (template без подстановки, агент читает из ENV). Прецедент: prewarm-spawn.sh CRITICAL fix
- **`--allowed-tools` без Write/Edit + spec через shell redirect** — для безопасного запуска LLM-помощника: tools = только Read/Glob/Grep, результат идёт в stdout, hook сам пишет файл. Альтернатива `--dangerously-skip-permissions + Write` опасна (LLM пишет произвольные пути)
- **Относительный порог `< N% от reference`** вместо `> 0` для sanity check числовых полей — когда в контексте есть эталон (цена, retail, объём). Ловит мусор от bulk-upload (1.01 при цене 2000 — потерянный множитель в Excel) который абсолютный `> 0` пропускает тихо. В ответе API возвращать `current_value` + `is_suspicious` чтобы UI показал проблему (P29, commit 433b433)
- **`.claude/agents/*.md` frontmatter `model:` подхватывается live** — замена `model:` в subagent definition не требует рестарта Claude Code, срабатывает при следующем `Agent(subagent_type=...)`. **Текущая политика (2026-04-21): opus 4.7 везде** — пользователь на Max plan, cost = 0, важнее качество рассуждений. Это замещает старую рекомендацию «opus для reviewers, sonnet для реализации, haiku для docs». См. `memory/feedback_model_always_opus.md`. Прецеденты: commit b52e8d1 (первая миграция reviewers на opus), 2026-04-21 (всё на opus).
- **Override на дочернем уровне → пересчёт производных полей**. Когда поле может быть переопределено (`box_size_override`, `pcs_per_box_override`, `per-vehicle overrides`) — все зависимые расчёты (`volume_m3`, распределение `delivery_rub`, стоимость логистики) должны использовать `effective_value = override ?? source` И пересчитываться при любом изменении override. Не хранить «снимок» от момента создания. Прецедент: supply-chain коммиты 8c565f0, a72a205 — volume_m3 не пересчитывался при смене override
- **Auto-detect колонок при Excel-paste по характеристикам**, не по фиксированному порядку. Определять тип колонки через эвристики: разделитель `*x× х` для box-size, наличие `.` или `,` для decimal, диапазон int, формат даты. Нормализовать строки ДО сравнения (`*` / `x` / `×` / `х` в box-size — все варианты). Любой порядок Excel-файла должен работать. Прецедент: supply-chain paste коммиты 7254bd8, 002f5c2
- **`alembic upgrade || echo skipped` в entrypoint = silent schema drift → 500 в проде**. Всегда fail-fast: миграция падает → контейнер не стартует → CD откатывает. Плюс env variables через `POSTGRES_PASSWORD:?error_msg` вместо fallback на default — запуск без `.env` громко падает, не с обфусцированной ошибкой позже. Прецедент: коммит e8b0c70 (audit 3 CRITICAL)
- **Secure-default + lifespan-guard для открывающих prod-флагов** (`REGISTER_ENABLED=true`). Default `False` в коде + runtime assert в lifespan если `ENV=production and REGISTER_ENABLED=True` (или whitelist только через explicit env). Defense-in-depth. Сопутствующий паттерн: `# no-soft-delete-check: <reason>` — точечный whitelist для ужесточения конвенции с backward-compat (commit fe5d74f превратил warn в error)
- **Partial index `WHERE is_deleted = false` через `CREATE INDEX CONCURRENTLY`** — обязательный паттерн для таблиц с SoftDeleteMixin где 90%+ запросов фильтруют по этому флагу. Без CONCURRENTLY — lock всей таблицы на минуты, с CONCURRENTLY — online. Важно: в Alembic revision убрать `with op.batch_alter_table(...)` и использовать raw SQL или `op.execute("CREATE INDEX CONCURRENTLY ...")` + `op.get_bind().execution_options(isolation_level="AUTOCOMMIT")`. Прецедент: коммит 5cb4d11 (partial indexes + worker memory 512→768M)
- **Scheduler cron для external-API sync = окно публикации поставщика, не рабочее время**. WB публикует финотчёт за прошлый день 03-05 MSK — ранний слот `05:00 MSK` + страхующий `08:00` + добор `14:00`, не «один прогон в 10:00 когда мы пришли на работу». Добавлять ранний слот если данные нужны к утреннему дайджесту/отчётам. Прецедент: commit 5fd7291 — добавили `wb_finance_daily_05` к существующим 08/14
- **`ON CONFLICT UPDATE x = excluded.x` поверх partial-fetch затирает реальные значения нулями** — если внешний API за день вернул данные за SOME nm_ids (часть chunks 429/SKIPPED по time-budget), `has_ad_data=True` (day_ads непустой), но для многих nm `excluded.adv_sum=0`. UPSERT перезаписывает прежние реальные значения нулём → дашборд показывает 0 spend, при этом per-campaign таблица заполнена. Решение: `update_fields["adv_sum"] = func.greatest(stmt.excluded.adv_sum, Model.adv_sum)` — реальное (>0) значение никогда не упадёт до 0 от тихого partial sync. Trade-off: если spend легитимно стал 0, останется stale-overstate (приемлемо для рекламных дашбордов — лучше overstate чем тихий зануляющий upsert). Для принудительного reset — отдельный прямой UPDATE (как в `batch_resync_ads`). Прецедент: project Вяткин (id=15), 30.04–02.05 у `wb_funnel_daily.adv_sum=0` при заполненном `wb_ad_campaign_daily`. Применимо везде где partial-sync поверх UPSERT cumulative-метрик (ad spend, views, clicks, любые накопительные счётчики из rate-limited API).
- **Force-pull mutable external fields на каждой синхронизации (best-effort, не блокирующее)**. Если поле может измениться вне нашего контроля (склад в кабинете WB, статус заказа, vendor_code) — не доверять локальной копии, дёргать external API при create/update/manual-refresh. Реализация: `_try_force_enrich_*` с try/except (fail external API не должен ломать business action). Trigger-list: create-from-linked, update, явная кнопка «Refresh from X». Прецедент: коммит 6927649 (assembly create/update + analytics.refresh_from_fbo force-pull warehouse_name из WB detail; race с enrich-job 3h оставлял заявки «без склада»)
- **Idempotent seed по per-project flag** — startup lifespan с N×M INSERT для уже засиженных проектов = startup >5 мин на 70k+ проектах через PgBouncer. Решение: один SELECT `... WHERE project_id = ANY(:pids) GROUP BY project_id` определяет seeded множество, INSERT только для новых. Гранулярность «проект целиком засеян или нет» достаточна (atomic full-set seed). Прецедент: коммит 6afa7fb (default_categories.py, worker startup 5min → 3sec)
- **Security-fix с блокирующим поведением (`raise`, lifespan-guard, pre-commit block) ОБЯЗАТЕЛЬНО сверяй с `memory/feedback_*.md`**. Generic OWASP-паттерн может быть намеренной feature владельца. Прецедент 2026-04-21: security-агент применил `raise RuntimeError("REGISTER_ENABLED=true in production is forbidden")` при старте FastAPI без чтения `feedback_register_enabled_prod.md` (где явно написано «открытая регистрация намеренна»). После merge прод крашился в бесконечном autoheal-цикле, пока не откатили через SSH + hotfix (RuntimeError → warning log). Правило зафиксировано в `.claude/agents/security-reviewer.md` секция «ОБЯЗАТЕЛЬНЫЙ первый шаг — context check». Альтернатива блокирующему фиксу: warning log + запись в learnings.md
- **Denormalized FK на дочерней сущности → синхронизировать при изменении parent.fk, иначе drift**. Когда child хранит копию parent.fk для индексации/фильтра (`inbound_receipts.warehouse_id` копируется из `cost_orders.target_warehouse_id` на DISPATCHED), при последующем `update_parent({fk: new})` ОБЯЗАТЕЛЬНО синхронизировать child.fk с state-guard: разрешено только в «pending» состоянии (EXPECTED), запрещено если child уже engaged (`ACCEPTED` → товар в `stock_movements`). Без sync — child застревает в старом scope (V-0001 висел в «Ожидаемых поставках» нового склада, но кнопка «Принять» недоступна). Generic паттерн для всех мест где child денормализует parent.fk. Прецедент: коммит a8e8d5f (`update_vehicle` + recovery-script `fix_inbound_warehouse_drift.py`).
- **Derived "first event date" через `MIN(events.date) WHERE condition`, не через external API**. Для полей типа first_sale_date / first_login / first_payment — лучше backfill через имеющуюся event-таблицу (`MIN(wb_funnel_daily.date) WHERE orders_count > 0`), чем дёргать WB API per-SKU (rate-limit, время, лимиты ключа). Backfill идемпотентен (повторный запуск не вредит), best-effort hook в существующий sync, не отдельный job. Прецедент: коммит 1eb4b4b (Nomenclature.first_sale_date через wb_funnel_daily, без WB API).
- **Не доверять кэшированному derived полю в parent если его дёшево пересчитать из source — особенно когда parent нестабилен**. После ребренда WB nm_id меняется, `Nomenclature.first_sale_date` теряет связь со старыми событиями → бейдж "Тип товара" врёт. Решение: на читающих endpoints (`get_by_sku`, `get_stock_analytics`) считать `MIN(wb_funnel_daily.date)` напрямую вместо JOIN на nomenclature. Cache-как-truth работает только если parent.id стабилен. Прецедент: коммит c31a90b (localization+stocks обходят `Nomenclature.first_sale_date`).
- **Single source of truth для derived UI status (бейджи / status-tags)**. `computeProductStatus(first_sale_date)` в одной утилите (`lib/utils/productStatus.ts`), переиспользуется на 3+ страницах (Номенклатура, Локализация, Складская аналитика, Excel-экспорт). Меняется правило (например, "Новинка" с 40д на 60д) — меняется в одном месте, бейджи синхронны на всех экранах. Прецедент: коммит c31a90b (computeProductStatus shared между nomenclature и localization).
- **Split/distribute логика над heterogeneous entities → strict-matching default + explicit opt-in для overrides**. Когда qty распределяется между несколькими FOI/строками с разными атрибутами (price/box/ppb), default-поведение должно консьюмить ТОЛЬКО matching entities; spillover на non-matching — отдельный режим под user opt-in («overwrite» modal). Без этого silent split на FOI с `price=0` или другой ценой → wrong-cost для большой доли qty без видимого алерта. Реализация: `splitRowAcrossFois(rows, withOverrides=false)` consume только подходящие, остаток оставляет unbooked → UI surfaces mismatch modal. Прецедент: V-0008 prod incident (project 4, May 8) — 24 баркода в FO 76/20 с дублированными cost_order_items: 6 на price_cny=0, 8 на чужой цене (95% qty с wrong unit cost). Фиксы: 974bbe4 (split base) → bbad93a (cumulative consume) → 64f8e4c (strict matching).
- **3+ итерации fix-on-fix одного бага = синдром «нет prod-fixtures в тестах»**. Если первичный fix не покрыт тестами на реальных prod-данных, каждая итерация ломает что-то ещё под продакшн-нагрузкой. Шаблон рецидива: 974bbe4 (split + 13 synthetic tests) → bbad93a (cumulative consume + 2 синтетических) → **64f8e4c (V-0008 prod fixtures: zero-price FOI, different-price FOI, single-FOI sufficient — +5 тестов из реального инцидента)**. Правило: после второго fix-fix запросить у пользователя минимум 1 production-fixture (сэмпл реальных данных где сломалось) и заложить в тесты. Иначе третий fix всё ещё будет вслепую.
- **Cumulative consumption через shared map при последовательной обработке списка**. Когда несколько строк обрабатываются последовательно и каждая «откусывает» из общего пула (FOI.remaining_qty, склад stock, лимит rate-limit) — передавать `consumed: Record<id, qty>` как опциональный mutable state в pure-функцию. Effective availability = `pool[id] - consumed[id]`. Без этого каждая строка видит full available → double-booking → backend rejects mid-transaction → откат всех. Прецедент: коммит bbad93a (`splitRowAcrossFois(consumed?)`); generic паттерн для warehouse stock allocation, rate-limited batch sync, любого «greedy distribute over shared pool».
- **External-API integer ID → semantic mapping проверяй на реальных данных, не доверяй коду из других проектов / Github gists / документации**. WB `/api/tariffs/v1/acceptance/coefficients` отдаёт `boxTypeID` (2/5/6) — public docs молчат, чужие маппинги `{2:mono, 5:super, 6:box}` оказались неверны. Реальный маппинг определён сверкой со скриншотом WB-кабинета: для конкретного склада (Екатеринбург - Перспективная 14) и SKU (одеяло 9кг) `boxTypeID=5 → deliveryCoef=175, storageCoef=215` совпало со вкладкой «Монопаллетой». Правильный маппинг `{2:super, 5:mono, 6:box}`. Без верификации моно-склады (Великий Камень, Владивосток, Хабаровск, Екатеринбург) попадали в «индивидуальная квота» вместо «бесплатно», assembly draft выбирал не тот package_type. Прецедент: коммит 4b5835e.
- **Cold-start distribution через share_pct, а не own-need, для SKU без продаж в регионе**. `warehouse_need_service` считает need только по складам где у SKU были продажи. Для новинки / SKU без истории в регионе (ДВ) need=0 — но WB кабинет рекомендует моно туда (ДВ = 18% продаж проекта). Решение: если cold_start доступен, distribution полностью пересчитывается через `recomputeColdStartAlloc(total_need, main_warehouses, minPack)` где shares берутся из `coldStartData.main_warehouses[].share_pct`. Сумма по строке = total_need (без double-counting). Fallback на own-need только если cold_start отсутствует. Прецедент: коммит 06c0439.
- **Acceptance-tooltip: различать «бесплатно/платно/квота» через 2 поля, не bool**. Endpoint `/acceptance/coefficients` возвращает кучу слотов с разной стоимостью; UI должен показать (a) сколько дней бесплатно, (b) сколько платно с минимальным коэффициентом, (c) есть ли «индивидуальная квота». В response: `paid_days_14 + min_coefficient`. Формат tooltip: `free>0 paid=0`→«бесплатно N/14», `free=0 paid>0`→«только платно N/14 мин ×K», `free=paid=0`→«по индивид. квоте», `free>0 paid>0`→«бесплатно N/14 + платно M/14». Шаблонизируется для любого external rate-limited резерва (приёмка, слот доставки). Прецедент: коммит 06c0439.
- **Двусторонняя канонизация имён warehouse: backend и frontend ДОЛЖНЫ генерить одинаковый canonical-ключ** (одинаковая функция / одинаковая таблица алиасов). Если backend режет «Самара (Новосемейкино)» в «Самара», а frontend дописывает колонку из `acceptance.distribution` где остаётся canonical — `have.has(...)` false → дублируются колонки в матрице. Решение: `_normalize_wb_warehouse` повторяет алгоритм `_normalize_acceptance_wh` и возвращает форму из `WAREHOUSE_COORDS`. Self-alias («Самара (Новосемейкино)»→канон и «Самара»→канон) нужен чтобы все 3 формы (orders short, stocks long, acceptance) сходились в одну строку. Прецеденты: коммиты 7777775 → 6221684. Generic паттерн для всех мест где BE и FE независимо «нормализуют» внешний ключ для матрицы.
- **Composite priority chain для derived field**: `per-scope override → SKU-level override → derived-from-fact → derived-from-plan`. На примере `box_multiplicity`: `box_qty_per_warehouse → Nomenclature.box_qty_override → last DELIVERED CostOrderItem.pcs_per_box_override → FactoryOrderItem.pcs_per_box/mix_pcs_per_box`. Реализация: `resolve_effective_ppb_for_assembly(barcode, rf_id)`. Use-flag отдельная цепочка: per-RF use побеждает SKU-level use. ## Антипаттерны (не повторять)
- `SELECT *` в продакшн запросах — всегда указывай колонки
- Пропуск type annotations на возвращаемых значениях сервисов
- Создание миграции без проверки `alembic heads`
- `.scalars().all()` без `.limit()` на больших таблицах
- `except Exception` без `asyncio.CancelledError` в scheduler jobs
- **Ранний `exit 0` в shell hook на основе одного условия блокирует все последующие блоки.** При добавлении нового блока в существующий hook — убедись что предыдущие условия не вылетают раньше. Решение: использовать пустые placeholder-значения вместо exit
- **`grep -c | ... || echo 0`** — на пустом stdin даёт многострочный результат («0\n0»), ломает арифметику в `[ "$x" -gt N ]`. Решение: `grep ... | wc -l | tr -d ' \n'` + `: "${var:=0}"` для дефолта
- **JS template literals в YAML literal block** (`script: |` в actions/github-script) — backtick-строка с `${var}` ломает YAML parser, потому что многострочный текст без отступов нарушает literal block. Решение: использовать `array.join('\n')` вместо template literal, или одинарные кавычки + конкатенация
- **Cron workflow с pytest/runtime без docker compose setup** — ubuntu-latest runner чистый, БД/Redis/MinIO не подняты. Без `docker compose up` (как в test.yml) тесты упадут с connection errors → false positive issue → spam. Либо setup, либо lightweight check (import + ruff). Прецедент: удалён `test-sentinel.yml` 2026-04-20
- **`$$` в bash subshell даёт PID родителя, не subshell** — `( echo $$ > lock ) &` пишет PID родительского процесса, который завершится через секунду → lock невалиден. Решение: `${BASHPID:-$$}` (BASHPID только в bash 4+, на macOS дефолт bash 3.2 → unbound variable с `set -u`). Прецедент: prewarm-spawn.sh lock не работал
- **`auto-merge.yml` блокирует PR при ЛЮБОМ check failure** — `claude` (Claude Code Review) всегда failed на PR с изменением `claude-review.yml` (workflow validation self-modify) → auto-merge скипается навсегда → требуется ручной merge. Решение: whitelist в `.jq select(.name != "claude")`. Прецедент 2026-04-20
- **`timeout-minutes` GH Actions должен покрывать max polling + retries + buffer** — мой post-merge.yml ставил 8 мин при cd-production реальном времени 8-9 мин → workflow убивался ДО завершения healthcheck. Формула: `timeout >= max_wait_polled + retries_time + 5min_buffer`
- **Hardcoded `sleep N` для ожидания workflow** — нестабильно, реальное время варьируется (cd-production: 8-9 мин в моём проекте, не 3). Лучше polling GH API: `gh api ... | jq` в `for` loop с timeout cap. Дожидаемся реального события, не угадываем
- **Claude Code Review failure при self-modification** — `anthropics/claude-code-action@v1` валидирует что claude-review.yml на PR == default branch. Если PR меняет сам workflow → expected failure «Workflow validation failed». Самоисправляется после merge в main. Игнорировать на первом PR с изменением workflow
- **Pre-commit `trim-trailing-whitespace` модифицирует файл → коммит падает** — hook detected trailing space, сам исправил и вернул exit 1 → «files were modified by this hook». Фикс: `git add <modified-file>` повторно + `git commit` заново с тем же message. НЕ `--amend` (коммит не создавался, amend модифицирует ПРЕДЫДУЩИЙ коммит). Частая жертва: markdown с code-blocks где пробелы после ``` или в pseudo-code. Прецедент: commit b52e8d1 — codemod.md
- **`pytest-xdist -n auto` в Docker с RAM limit → OOM (exit 137)** — `auto` спавнит по кол-ву CPU (8 на моей машине) × test-worker overhead ≈ >2GB → SIGKILL от Docker memory limit. Фикс: `-n 2` (2 воркера, ~7-8 сек на DDS2 test suite vs 30-60 сек без xdist). Tradeoff: 2× ускорение вместо 4×, но стабильно. Если backend container raise memory limit > 4GB → можно `-n 4`. Прецедент: commit 4587fea → откат в следующем коммите
- **Subagent в Phase 2 игнорирует `isolation: worktree` constraint и пишет абсолютные пути** — backend-агент Phase 2 counterparties (2026-04-21) получил инструкцию «relative paths only» в промпте, но всё равно сделал Write/Edit на `/Users/a1/Desktop/dds_app/backend/...` (main dir) вместо своего worktree. После merge в dev — дубли файлов staged в main dir, 10 минут cleanup. Жёстче: в промпте teammate ЯВНО говорить путь worktree (получить из результата `git worktree list`) и сказать «каждый Write/Edit должен начинаться с `./` или быть относительным от `<worktree-path>`. Не использовать `/Users/a1/Desktop/dds_app/` НИКОГДА кроме Read reference». И/или добавить pre-Write валидатор в hook (пока нет). Прецедент: worktree agent-a9ac9883 → commit 7a8c70c
- **Pre-commit loop blocks long-running subagent** — в Phase 2 backend-агент застрял в цикле «pre-commit ruff падает → агент правит → снова падает → снова правит», ушло 10+ минут на разные варианты RUF001 (кириллица в hardcoded ИНН→имя), S324 (sha1), S314 (xml), E712 (`is_deleted == False` в SQLAlchemy expr). Решения для агентов: (1) для файлов с hardcoded русскими названиями (`scripts/backfill_*.py`, `backend/etl/master_logic.py`, ETL парсеры) — СРАЗУ добавлять `# ruff: noqa: RUF001, RUF002` первой строкой файла (до docstring); (2) `hashlib.sha1(..., usedforsecurity=False)` для deduplication hash; (3) SQLAlchemy `== False` в where-clause оставлять с `# noqa: E712 — SQLAlchemy expression`; (4) XML.etree для trusted user uploads — `# noqa: S314 — trusted user upload` (пока нет defusedxml); (5) если pre-commit падает 2 раза подряд на одном файле — fail-fast, вернуть отчёт lead-агенту, НЕ крутить цикл. Прецедент: agent-a9ac9883 остановлен вручную через TaskStop после 25 мин вместо запланированных 15
- **UPSERT с дублями ключа в одном INSERT batch → CardinalityViolation** (`ON CONFLICT DO UPDATE command cannot affect row a second time`). Postgres не разрешает несколько INSERT-row с одним unique key в пределах одного statement. Возникает когда внешний API возвращает строки в более узкой грануляции чем твой unique key (WB `/supplier/stocks` отдаёт per barcode/size, у нас `uq (project_id, nm_id, warehouse_name)`). Решение: дедуп в Python ДО executemany — агрегировать в `dict[key] -> row` с правилом merge (sum для qty, first-non-empty для строк). Снапшот-таблицы с PK=id остаются per-row, агрегируется только UPSERT-target. Прецедент: коммит 01a9cd9 (wb_stocks, проект 15 был с пустым `wb_warehouse_stocks` → /warehouse/wb-stocks не работал)
- **TanStack table: client-side sort + server pagination = иллюзия глобальной сортировки** — сортировка применяется ко всему датасету, но `pageSize=N` показывает только срез; при клике sort на не-первой странице пользователь видит «не топ значения» и думает «sort сломан». Решения по объёму: ≤2-5k строк → `enablePagination={false}` (всё в одной таблице, реальный sort визуально подтверждён); >5k → server-side sort+pagination (sort param в API, query refetch при изменении). Прецедент: коммит 41d177d (Единые остатки, 1023 SKU)
- **`pytest -n N` без `--dist=loadfile` флейкает при autouse фикстурах с общим resource** (`DELETE FROM ... WHERE project_id = :shared_id` в conftest). xdist дефолт `--dist=load` распределяет тесты по воркерам без учёта файла → два теста из разных файлов с одним и тем же autouse cleanup гоняют race на shared row → `StaleDataError`. Решение: `--dist=loadfile` в `pytest.ini` — все тесты одного файла исполняются на одном воркере, parallelism сохраняется между файлами. Прецедент: коммит 5115c5e (pre-push pytest -n 2 непредсказуемо флейкал)

Subagent Phase 2 работал 14-25 мин, пользователь думал что Claude завис. Правило: если ожидаемое время выполнения >5 мин, агент запускается в background, главный процесс продолжает работу. Проверять прогресс через `git status` в worktree (видно сколько файлов создано) или размер `output_file`. НЕ читать full output файл — он огромный JSONL, перегрузит контекст. Прецедент: commit 7a8c70c + feedback_agent_visibility.md
- **`paths-filter` в `test.yml` без `scripts/**` → recovery-PR замораживается auto-merge'ом** — auto-merge ждёт required checks (Tests, Security Audit). Если PR трогает только `scripts/**` (one-off recovery-скрипты, например cancel ASM-6) и `paths-filter` не включает `scripts/**` → workflow не запускается → required checks остаются "Expected" навечно → PR висит. - **JS `\b` regex НЕ матчит кириллические границы слов**. В JS `\w` = `[A-Za-z0-9_]`, кириллица не word-char → `\bСГТ\b` ложно срабатывает на «Ярославль СГТ» (граница до «С» — там кириллица, не word-char для JS-движка). Для фильтра подстроки по списку маркеров (СГТ/Питание/Горючее/виртуальные/СЦ) использовать `includes()`/`indexOf()` на нижнем регистре, не regex. Альтернатива при необходимости regex — Unicode property escapes (`/\p{L}/u`) или ECMAScript `v` flag, но прямая `\b` не работает. Прецедент: коммит 06c0439 (`isSpecWarehouse`).
- **Pre-push НЕ запускает mypy → ошибки типизации улетают в CI**. `.git/hooks/pre-push` запускает только pytest-testmon + vitest + conventions + slopsquatting, но не mypy. CI ловит `error=` kwarg в `logger.warning()` (stdlib logger без structlog не понимает kwargs), `int(wid)` перед dict.get когда key — `int`, `if barcodes else True` где barcodes гарантированно non-empty (тип-narrowing уже исключил None/empty). Решение: либо добавить `mypy backend/` в pre-push (медленно: 5-10s), либо `mypy --diff-only` через `git diff --name-only HEAD~..HEAD -- '*.py'` (быстрее). До инфраструктурного фикса — самопроверка через `make typecheck` перед `git push`. Прецедент: коммит a92738b (типизация box_multiplicity + warehouse_acceptance, CI red на dev).
