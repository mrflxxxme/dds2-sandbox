# Plan — DDS2

> **Когда какой tier:**
> - `/plan` (этот) — backend-only или frontend-only задачи средней сложности (3-5 файлов)
> - `/spec` — фича с 2-5 файлами и формальной спекой (regression 6% → 2%)
> - `/ultraplan` ☁️ — cross-domain (3+ DOMAIN), миграция auth, новый домен — облачное планирование с 3 explorer + critic

Эта команда создаёт план реализации ПЕРЕД написанием кода.

## Что делает

1. **Анализ требований** — что нужно построить
2. **Чтение DOMAIN_*.md** — контекст затронутых доменов
3. **Пошаговый план** — фазы реализации по Agent TDD
4. **Риски** — потенциальные проблемы и блокеры
5. **ЖДЁТ подтверждения** — НЕ пишет код без "ок"

## Когда использовать

- Новая фича
- Архитектурные изменения
- Сложный рефакторинг
- Затрагивает несколько доменов

## Процесс Agent TDD

```
Фаза 0: Анализ → ТЗ → подтверждение
Фаза 1: Model → Migration → Schema (последовательно)
Фаза 2: Backend ∥ Frontend (параллельно)
Фаза 3: pytest + check_conventions → коммит
```

## После подтверждения

- `/tdd` — реализация с тестами
- `/build-fix` — если ошибки сборки
- `/review` — ревью реализации
- `/verify` — финальная проверка

**КРИТИЧНО**: Плановый агент НЕ пишет код до явного подтверждения "ок" или "proceed".
