# /learn — рефлексия и синхронизация docs

Запускать после завершённой фичи / бага / рефакторинга. Автотриггер — Stop-hook сообщает о pending-коммитах.

## 1. Собери коммиты
Прочитай `.claude/.pending-learn.log` (пишет post-commit hook). Пусто → возьми последние 3 коммита (`git log --oneline -3`). Для каждого: `git show --stat <hash>` + точечные диффы.

## 2. Извлеки уроки
- **Новый антипаттерн** (повторяющаяся проблема) → check в `scripts/check_conventions.sh` + запись в `.claude/rules/learnings.md`.
- **Новый рабочий паттерн** → запись в `learnings.md`; повторяется 3+ раз → шаблон в `.claude/templates/`.
- **Исправлен баг** (коммит `fix:`) → перенести запись в `memory/project_known_bugs.md`.
- **Новый баг / техдолг** (`TODO` / `FIXME` / workaround в коде) → добавить в `project_known_bugs.md`.
- **Feedback** (коррекция поведения агента или подтверждение нестандартного решения) → новый/дополненный `memory/feedback_*.md`.

## 3. Синхронизируй документацию
По diff определи затронутые домены и обнови:
- `backend/DOMAIN_{X}.md` — новые модели / сервисы / эндпоинты, изменённое поведение.
- `backend/DOMAIN_INDEX.md`, `MAP.md` — если появился новый домен или ключевой файл.
- `CLAUDE.md` — новый домен, новый антипаттерн, изменение iron rules.
- Новый кэш-prefix → проверить `invalidate_project_reports()` в `backend/cache.py`.

## 4. Очисти логи
`> .claude/.pending-learn.log`.

## Правила
- Только дополняй существующие файлы (исключение — новые шаблоны). Не дублируй уроки — сперва прочитай текущие `learnings.md` / `feedback_*`.
- Минимальные правки, только реальные изменения. Нечего извлечь — так и скажи, очисти лог.
- Коммит — никогда автоматически, решает пользователь.
