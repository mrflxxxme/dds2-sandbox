# /build-fix — починка сборки

Чинит ошибки сборки и тестов по одной, минимальными diff. Без рефакторинга.

## Команды сборки
| Компонент | Команда |
|-----------|---------|
| Backend-тесты | `docker compose exec backend pytest tests/ -x --tb=short` |
| Конвенции | `bash scripts/check_conventions.sh` |
| Docker build | `docker compose build backend` |
| Frontend build | `cd frontend-react && npm run build` |

## Процесс
1. Запустить, захватить вывод, сгруппировать ошибки по файлам, отсортировать по зависимостям (сначала импорты/типы, потом логика).
2. По каждой ошибке: прочитать контекст → диагностировать корневую причину → минимальный фикс → перезапустить.
3. Long-running команды (pytest, docker build) — гонять через `Monitor` tool: первая ошибка ловится сразу, не после всех тестов.

## Стоп-сигналы (остановиться, спросить пользователя)
Фикс плодит больше ошибок; та же ошибка после 3 попыток; нужны архитектурные изменения; ошибки из-за отсутствующих зависимостей.
