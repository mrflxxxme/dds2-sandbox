Газелька (`gazelka_service.py` + `integrations/gazelka_client.py`) — единственная интеграция DDS2, у которой КАЖДЫЙ успешный POST создаёт реальный заказ у перевозчика; API нет, только cookie-сессия и form-POST, отмены заказа нет ни в UI, ни в коде.

**Why:** цена ошибки — живые деньги и груз, уехавший не туда. Ложный «не создалось» так же вреден, как ложный «создалось»: из него растёт ре-сенд и второй реальный заказ.

**How to apply:** при ревью любого изменения в этой зоне (включая фронтовую модалку) проверять по порядку:
1. Идемпотентность отправки: `_last_sent` обязан ключеваться ПАРОЙ (kind, doc_id) — счётчики сборок и переездов независимы, id 55 существует в обоих.
2. Дискриминатор заказа в портале: у сборки — № поставки WB, у переезда его нет вовсе → маркер «TR-№» в notes, приклеиваемый принудительно на бэке. Без дискриминатора `_plan_matches_payload` падает на «даты + паллеты», и чужая заявка того же дня матчится как наша.
3. `None` в payload = «оставить дефолт формы портала» (`_merge_payload`), а дефолт select'а — первая/`selected` опция, т.е. ЧУЖОЙ склад маркетплейса. «Пусто» обязано ехать явной пустой строкой; фронтовый идиом `value || null` этот контракт молча ломает.
4. Авто-действия синка (машина, авто-шип) двигают сток и деньги — сверять, из каких статусов они разрешены, и что фронтовый гейт «Отправить» не обходится `allowed_from`-путём.
5. Ручные гарды (`_deny_if_gazelka_leads`) не должны создавать тупик: документ под агрегатором нельзя ни оформить руками, ни отправить, если портал так и не прислал машину.
