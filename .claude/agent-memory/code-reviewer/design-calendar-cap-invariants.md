Волна A (2026-08, ветка `claude/dialog-analysis-improvements-9f7e8f`) ввела в модуле явный принцип **«тихое усечение запрещено»**: `GET /calendar` тянет `limit+1` строк и отдаёт `truncated: bool` (cap 500 в режиме `month`, 2000 в режиме диапазона, окно всегда запрошенное ±6 дней, максимум 400 дней). Фронт обязан показывать баннер `DESIGN_UI_HINT.calendarTruncated`.

**Дыра того же принципа рядом:** список «Отложенные/Отменённые» на доске (`design-tasks/page.tsx`, `api.listDesignTasks({status:[scope], limit:200})`) режется молча — 200 это ещё и жёсткий потолок роутера (`limit: int = Query(100, ge=1, le=200)`), пагинации нет, а кнопка рядом показывает ПОЛНЫЙ счётчик из `counts` ответа `/board`. Не регрессия волны (тот же cap был в удалённом `HoldCancelledOverlay`), но теперь противоречит собственному контракту модуля. Поднято на ревью волны A, фикса на момент ревью нет.

**Второй край того же кода:** `resolve_calendar_window` расширяет границы на ±6 дней БЕЗ клампа — на `date.min`/`date.max` (`date_to=9999-12-31`) `date + timedelta` кидает `OverflowError`, а `_svc` в роутере мапит только `ValueError`/`PermissionError` → 500 вместо 400. Режим `month` этой дырой не страдает: там `date(year+1,1,1)` даёт `ValueError` → 400.

**Why:** оба факта — про границу «что считается контрактом», а не про баг реализации; следующий ревьюер иначе потратит время на перепроверку каждой из двух кап-констант.

**How to apply:** при ревью следующих волн модуля — сверять, появился ли сигнал усечения у off-board списка, и не скопировали ли `±6 дней` без клампа в новые ручки. Смежное: [[design-transitions-canon]], [[design-allprojects-rbac-tension]].
