Наследование новых разделов у editor/viewer (`backend/rbac.py: inherited_pages` + `ProjectMember.pages_updated_at`, ревью 2026-07-30, на тот момент код был uncommitted).

**Отзыв доступа держится РОВНО на одной строке.** `pages_updated_at = utcnow()` в `update_member_role`
(`backend/routers/projects.py`). Убери её — снятая владельцем галочка возвращается наследованием на
следующем же чтении (у участника с водяным знаком раньше `PAGE_ADDED_AT[page]`). Пьюр-тест
«снятая галочка не вернулась» этого НЕ ловит, если проверяет страницу из начального каталога
(`fbo`, дата = `CATALOG_BIRTH`): она старше любого водяного знака, тест зелёный и без бампа.
**Как применять:** правишь `update_member_role`/`accept_invite`/`register` — проверь, что бамп на месте, и
что тест берёт страницу с датой ПОЗЖЕ водяного знака.

**Гарды синхронизации каталога фронт↔бэк никогда не выполняются.** `tests/test_conventions_sync.py::TestRbacPageKeySync`
(3 теста: чекбоксы «Команды» ⊆ ALL_PAGES, ALL_PAGES ⊆ чекбоксы, pageKey сайдбара ⊆ ALL_PAGES) читают
файлы `frontend-react/` и делают `pytest.skip`, если их нет. Все документированные прогоны
(`docker compose exec backend pytest`, `make test-*`, CI `test.yml`) идут В КОНТЕЙНЕРЕ, где
frontend-react отсутствует → 3 skipped ВСЕГДА. Проверено прогоном: `18 passed, 3 skipped`.
**Как применять:** не считать эти тесты гардом (в `backend/MAP.md` они заявлены как гард); реальную сверку
каталогов делать в vitest или дампом ALL_PAGES в JSON-артефакт.

**Семантика `PAGE_ADDED_AT`.** Дата = день попадания ключа в `rbac.py` (сверено с `git log -S` — все даты
верны), а НЕ день деплоя; сравнение строгое по дню (`added_at <= cutoff` → не наследуется), водяной знак —
naive UTC. Отсюда три щели: раздел не доедет к тому, кого настроили в день добавления ключа; окно
«закоммичено, но не задеплоено»; ±3ч на границе суток MSK/UTC. Прошлая дата по копипасте = раздел не
наследуется никем (ровно тот баг, который лечили), будущая = наследуется всеми вечно; санити-гарда на
диапазон дат нет.

**Ширина наследования** — по секции `SECTION_PAGES`, плюс ветка `blanket` (кому выдали всё, что было на тот
момент, минус `PAGES_NEVER_INHERITED`) отдаёт новые разделы и вне его секций. На прод-копии (8 editor'ов):
[logistics, assembly] → +5 разделов (вкл. `fbs`, который пишет в WB); двое blanket-editor'ов проекта 15 →
+10, вкл. `ai-chat` (платные токены) и `supply-chain`. Бэкенд-гейт `require_role(page=...)` живёт только у
`dashboard`/`salary`/`raw-data`, так что для остальных страниц наследование = видимость в меню + `PageGuard`.
