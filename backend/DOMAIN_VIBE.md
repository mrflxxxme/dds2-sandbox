# DOMAIN_VIBE — Вайбкодинг (телеметрия репозитория)

Вкладка «Вайбкодинг»: что каждый вайбкодер выкатил на прод. Поток:
`git` → **CI считает** (`scripts/vibe_stats.py`) → **SSH в контейнер**
(`scripts/ingest_vibe.py`) → `vibe_commits` / `vibe_files` → `vibe_service` →
`GET /api/v1/vibe/me` → страница `/p/[slug]/vibecoding`.

## Четыре решения, которые легко «починить» обратно — не надо

**1. Данные считает CI, а не бэкенд.** На проде git недоступен: `.dockerignore:7`
исключает `.git` из образа. GitHub-токена на бэкенде нет и заводить его не нужно —
CI уже ходит на сервер по SSH (`DEPLOY_SSH_KEY`, тот же ключ, что у деплоя).
Воркфлоу `vibe-stats.yml` — **отдельный**, а не шаг `cd-production`: упавшая
статистика не должна ронять выкатку прода.

**2. Без `project_id` — осознанное исключение из Iron rule №1.** Это статистика по
коду самого DDS2, а не данные арендатора; коммит не принадлежит проекту клиента.
`check_conventions.sh` пометит сервис в «Check 7» — это ожидаемое предупреждение
(в том же списке `bank_directory`, `assembly/pallets`), не ошибка.

**3. Доступ — по строке в `vibe_authors`, НЕ по роли.** `role` живёт в
`ProjectMember` и она проектная: **клиент-селлер является `owner` своего проекта** и
прошёл бы любую проверку по роли, увидев внутреннюю кухню. Нет строки — нет вкладки
и 403 на API. На фронте пункт сайдбара гейтится флагом `requiresVibecoder`, который
**заменяет** `canAccess`, а не дополняет: `permissions.pages` никогда не содержит
`vibecoding` (страница не проектная), поэтому AND скрыл бы вкладку от вайбкодера-не-админа.
Состояние стартует с `false` — сетевой сбой или старый бэкенд вкладку не откроют.

**4. Маппинг «пользователь → git-почта» только руками** (`scripts/vibe_author.py`).
Почты в DDS2 и в git **не пересекаются ни у кого** (в сервисе icloud/mail.ru, коммиты
с gmail и локальных хостов) — автоматически связать нечем. У одного человека почт
бывает несколько: у Дениса `denlyublyukatyu@gmail.com` (21 коммит) и
`denisdmitriev@macbook-air-7.local` (5), причём **самый крупный коммит недели — под
второй**. Считать по одной почте = потерять треть работы и 57 файлов из 124.
Почты нормализуются в нижний регистр на всех концах.

## Грабли git, зашитые в `vibe_stats.py`

- **Дата АВТОРА, не коммитера.** `git log --since` фильтрует по дате коммитера, а
  ребейз на ушедший dev перебивает её днём пуша: работа вторника уехала бы в четверг.
  Берём широкое окно и режем по author date в Python. Та же грабля отдельно бьёт в
  `collect_new_paths` — там тоже широкое окно + фильтр по sha.
- **Новые файлы — отдельным запросом** (`--diff-filter=A`). Из `--numstat` их не
  вывести: у нового файла удалений 0, но и у чисто дополненного тоже.
- **Уникальные файлы ≠ сумма `files` по коммитам** — отсюда таблица `vibe_files`.

## Модель

| Таблица | Ключ | Смысл |
|---|---|---|
| `vibe_authors` | `git_email` uniq | маппинг + список доступа |
| `vibe_commits` | `sha` | поставка на прод; UPSERT по sha = идемпотентный ингест |
| `vibe_files` | `(sha, path)` | файлы поставки; при ре-ингесте перезаписываются целиком |

## Метрики

**Ритм** — дней с поставкой в скользящем окне 14 дней. НЕ стрик подряд: стрик
обнуляется за выходной и подталкивает коммитить мелочь ради цифры. Окно обрезается
по первой поставке автора и считается по окну, а не по периоду отчёта.

**Масштаб** — опись объёма: файлы, новые, компоненты, миграции, разделы, строки по
областям. Отвечает «сколько сделано», а НЕ «сколько стоит»: 58-строчная починка
лежащего прода может весить больше 5000-строчной страницы. **Денег в разделе нет
намеренно** — цифра не может быть одновременно автоматической и справедливой.
