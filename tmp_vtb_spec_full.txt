Термины и определения 
1. Банк – Банк ВТБ (ПАО). 
2. ЕИО - в рамках настоящей спецификации под ЕИО подразумевается единоличный 
исполнительный орган Клиента – юридического лица, а также Клиент – 
индивидуальный предприниматель или физическое лицо, занимающееся в 
установленном законодательством РФ порядке частной практикой. 
3. Клиент - юридическое лицо любой организационно-правовой формы (за исключением 
кредитных организаций) (резидент/ нерезидент), индивидуальный предприниматель 
или физическое лицо, занимающееся в установленном законодательством 
Российской Федерации порядке частной практикой, заключившее с Банком Договор о 
предоставлении 
услуги 
«Дистанционное 
банковское 
обслуживание» 
с 
использованием системы «ВТБ Бизнес» (Договора системы «ВТБ Бизнес»). 
4. Протокол SOAP – тип стандарта (протокола) для обмена структурированными 
сообщениями. 
5. Сервис ИБК – сервис «Интеграционный Банк-Клиент», предоставляемый в рамках 
Договора системы «ВТБ Бизнес» и обеспечивающей предоставление Клиенту 
возможности прямого обмена между собственной учетной системой Клиента (далее 
по тексту – ERP-система Клиента) и Банком ЭД и иными электронными запросами 
(сообщениями) соответствующего формата, отраженного в настоящей спецификации. 
6. Система «ВТБ Бизнес» – система дистанционного банковского обслуживания «ВТБ 
Бизнес». 
7. ЭД – электронные документы 
8. API 
(Application 
Programming 
Interface) 
– 
интерфейс 
прикладного 
программирования, который представляет собой набор протоколов и подпрограмм, 
позволяющих различным системам и приложениям взаимодействовать друг с другом, 
не требуя от разработчиков или конечных пользователей знания того, как они 
реализованы. 
9. Blob-таблица – специальный тип данных, предназначенный для хранения вложений и 
массивов данных. 
10. Host-to-Host (h2h) – канал информационного взаимодействия, обеспечивающий 
предоставление Клиенту сервиса «Интеграционный Банк-Клиент». 
11. TLS – криптографический протокол, обеспечивающий защищённую передачу данных 
между узлами в сети Интернет. 
12. Web-сервис – программное обеспечение, которое предоставляет доступ к своим 
данным другим программным продуктам через Интернет. 
13. WSDL – язык описания web-сервисов и доступа к ним. 
 
 
Термины и сокращения, не определенные в настоящем Руководстве пользователя и 
указанные в них с заглавной буквы, соответствуют терминам и сокращениям, определения 
которых содержатся в Условиях дистанционного банковского обслуживания (система «ВТБ 
Бизнес».

2. Общие требования по работе с API. 
Вызов сервисов доступен после прохождения 2-х факторной аутентификации. 
Для прохождения аутентификации необходимо передать: 
• 
Пара логин/пароль в формате Base64 (в виде login:password Base64) в заголовке 
authorization; 
• 
Сертификат УНЭП, выпущенный Удостоверяющим центом Банка на имя ЕИО. 


--- Page 6 ---
После прохождения аутентификации для вызова бизнес-сервисов необходимо использовать 
заголовок (frontcookie), полученный на шаге аутентификации, и сертификат УНЭП, 
выпущенный Удостоверяющим центом Банка на имя ЕИО. 
После аутентификации Клиент может обратиться к любым банковским сервисам, 
доступным через Сервис ИБК. 
В зависимости от типа передаваемых/запрашиваемых данных, дополнительно может 
потребоваться подписать передаваемый документ. Это позволит повысить уровень защиты 
данных.

8. Формирование данных для подписи документа 
Данные для подписи формируются в виде XML документа, он должен формироваться с 
точностью до байта в соответствии с правилами, изложенными ниже (необходимо 
избегать внесение любых преобразований, например, добавления пробелов между 
тегами). 
Данные для подписи представляют собой массив байт. Для преобразования строки в 
массив байт должна использоваться кодировка «windows-1251». 
В описании ниже #число означает символ с кодом “число”. 
1. Вначале должен выводиться текст 
«<?xml version="1.0" encoding="windows-1251"?>#13#10<Body>#13#10». 
2. Поля должны выводиться в том порядке, как они описаны в таблицах с полями 
запроса документа. Должны выводиться все поля, помеченные как подписываемые 
(Колонка S). 
3. В цикле по полям: 3.1. выводится один пробел, «<Field FieldName=», в кавычках (") 
название поля заглавными буквами (uppercase), один пробел, «DataType=», в 
кавычках тип поля (см. описание для конкретных типов полей Системе «ВТБ 
Бизнес»), затем: 
• 
если значение поля не указано (кроме полей с типом STRING), выводим один 
пробел, «NULL="true"/>#13#10» 
• 
иначе, выводим «>», форматированное значение поля (см. описание для 
конкретных типов полей Системе «ВТБ Бизнес»), «</Field>#13#10» 
• 
значение поля выводим, как описано в п. 3.3 без преобразования к формату XML 
(например, символ амперсанд записываем как " & ", а не как " &amp; "). 
Например: 
<Field 
FieldName=”REQUESTCONVRATE” 
DataType=”DOUBLE”>2.3700</Field> 
<Field FieldName=”REQUESTCONVRATE” DataType=”DOUBLE” NULL=”true”/> 
4. Выводится «</Body>». 
Заполнение атрибутов подписи 
Атрибуты подписи заполняются следующим образом: 
<Sign SignNum="1" SignOrder=”2” CryptLibID="8" UID="CN сертификат 1-й подписи"> 
Данные 1-й подписи документа в формате PKCS #7 по алгоритму 
GOST R 34.10-2012 в кодировке Base64 
</Sign> 
<Sign SignNum="2" SignOrder=”2” CryptLibID="8" UID="CN сертификат 2-й 
подписи "> 
Данные 2-й подписи документа в формате PKCS #7 по алгоритму 
GOST R 34.10-2012 в кодировке Base64 
</Sign>

Приложение 6. Описание типов полей 
 
Тип поля 
Описание 
STRING 
Формируется следующим образом: 
выводим «<![CDATA[», значение поля, выводим «]]>», например: 
<Field FieldName=”BENEFBANKPLACE” 
DataType=”STRING”><![CDATA[MOSCOW]]></Field> <Field 
FieldName=”BENEFBANKPLACE” DataType=”STRING”><![CDATA[]]></Field> 
Для вложений: необходимо перевести документ (вложение) в бинарный вид. 
Вывод каждого байта со значением от 0 по 31 или вывод символов ‘#’ и ‘]’ 
должен выполняться в виде #XX, где XX – код символа в шестнадцатиричном 
виде. 
INTEGER 
Блок (Содержимое поля) представляет собой в этом случае просто integer 
представление значения поля, переведенное в строку, например: 
<Field FieldName=”ISMULTICURR” DataType=”INTEGER”>1</Field> 
Пустое значение поля типа INTEGER эквивалентно значению «0». 
DOUBLE 
Блок (Содержимое поля) представляет собой в этом случае переведенное в 
строку представление double значения поля. 
Перевод осуществляется в представление с фиксированной точкой, с 
разделителем дробной части ‘.’ И с точностью 4 знака после запятой, 
например: 
<Field FieldName=”REQUESTCONVRATE” 
DataType=”DOUBLE”>2.3700</Field> 
DATE 
Блок (Содержимое поля) – это строковое представление даты в формате 
dd.mm.yyyy, например: 
<Field FieldName=”DOCUMENTDATE” DataType=”DATE”>30.06.2011</Field> 
Важно: Тип поля DATE не должен использоваться для полей вложенных 
таблиц (внутри BLOBTABLE), а должен использоваться тип DATETIME, 
независимо от того, передается только дата или дата со временем. 
DATETIME 
Блок (Содержимое поля) – это дата и время из значения DateTime в формате 
dd.mm.yyyy:hh:mm:ss.dddd, например: 
<Field 
FieldName=”TESTDATE” 
DataType=”DATETIME”>06.06.2011:02:15:54.0000</Field> 
Также применяется для передачи и хранения даты без времени. При этом, 
если значение представляет именно дату (без времени), значение должно 
быть указано в виде 06.06.2011:00:00:00.0000 - вместо времени обязательно 
должны быть нули «00:00:00.0000», например: 
<Field 
FieldName=”TESTDATE” 
DataType=”DATETIME”>06.06.2011:00:00:00.0000</Field> 
MONEY 
Блок (Содержимое поля) представляется также как и для типа double, 
например: 
<Field FieldName=”AMOUNT” DataType=”MONEY”>50.1000</Field> 
BOOLEAN 
Блок (Содержимое поля) представляет собой строки true или false в 
зависимости от значения поля, например: 
<Field FieldName=”BOOLFIELD” DataType=”BOOLEAN”>true</Field> 
<Field FieldName=”BOOLFIELD” DataType=”BOOLEAN”>false</Field>
