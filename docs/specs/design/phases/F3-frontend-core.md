## Goal

Полный рабочий цикл PRD §4 в браузере: создать → назначить → в работу → сдать → вернуть → пересдать → принять.

## In scope

`src/types/api.ts` (типы, зеркало схем Ф0 — предпочтительно `make sync-types` + доводка) · `src/lib/api/designTasks.ts` (`addDesignTaskMethods`) + строка в барель `src/lib/api.ts` · страницы `src/app/(main)/p/[slug]/design-tasks/`: `page.tsx` (доска + переключатель вида), `list/` или query-параметр вида, `new/page.tsx`, `[taskId]/page.tsx`, `components/`.

## Out of scope

Календарь, загрузка, сквозной (→ Ф5) · touch-dnd (→ потом, Р8) · панель метрик (→ Ф6).

## Работы

### Доска (вид по умолчанию)

6 колонок `BOARD_STATUSES`, `GET /board`. Карточка: номер · `WbThumb nmId` (при nm_id) · заголовок · исполнитель · срок (просрочка — цветом срока, не строки) · бейджи: 🔴 непросмотрено (`unviewed`), «срочно» (`is_urgent`, Р9 — подсветка, порядок не меняет), «аутсорс». Нативный HTML5 dnd (Р8: `draggable`, `onDragStart/DragOver/Drop` — прецеденты в `PalletLayoutTab.tsx`): перенос → оптимистичное перемещение → `POST /{id}/move {to_status, after_task_id}` → на 4xx откат + toast с текстом ошибки бэка + refetch. Перестановка внутри колонки доступна по `permissions.can_reorder` (иначе dnd только между колонками). Фильтр-тумблер «Отложенные (N) / Отменённые (N)» — списком-оверлеем (вне доски, PRD §4). Переключатель вида Доска|Список в шапке.

### Деталка `[taskId]/page.tsx`

Двухколоночная. Слева: суть (`description`), ссылка-кнопка на ТЗ-таблицу (`sheet_url`), товар (`WbThumb` + title, кнопка «привязать товар» с автоподсказкой при отсутствии nm_id), исходные материалы (плитка: файл/ссылка/артикул, скачивание). Справа: статус + кнопки действий строго по `permissions` с бэка (инвариант §6.9); история версий (карточка: №, автор, дата, комментарий, файлы, вердикт с причиной); модалка «Вернуть» не отправляется с пустой причиной; модалка «Сдать работу» (файлы + что сделал); тред комментариев; журнал переходов. При открытии лидом — `POST /{id}/viewed`.

### Создание `new/page.tsx`

Поля: название товара (текст + автоподсказка `GET /product-suggest` c debounce 300мс; выбор подсказки заполняет `nm_id`, ничего не обязывает — Р2), суть (textarea, min 10), ссылка на ТЗ-таблицу (обязательна, URL-валидация), тип работы, чекбокс «срочно», срок. Исполнителя НЕТ (дельта v4 — назначает лид). Материалы: три вкладки файл/ссылка/артикул (файл — через паттерн `DocumentUploader`).

### Список

Донор `ab-tests/page.tsx`: `PageGuard page="design-tasks"` → `PageHeader` → чипы со счётчиками (Все · Новые · Назначены · В работе · На проверке · Правки · Отложены · Просрочено) → фильтры (исполнитель, тип, срочные, поиск) → таблица: Номер · Товар (`WbThumb`+title) · Тип · Сложность · Срочно · Исполнитель · Срок · Версий · Статус. Сортировка по сроку.

### Правила вёрстки

Цвета — только `var(--color-*)`; числа — `formatNumber(x, 0)`; состояния loading/error/empty/data на каждой странице; `.claude/rules/design.md` подхватится по paths.

## AC

- **AC-1:** `cd frontend-react && npx tsc --noEmit` — чисто.
- **AC-2:** `npx vitest run` — зелёный (юниты на маппинг колонок и optimistic-откат).
- **AC-3:** Браузерный сценарий (webapp-testing): менеджер создаёт заявку (с подсказкой товара) → красная метка у лида → лид назначает → дизайнер тянет в «В работе» → сдаёт версию → менеджер возвращает с причиной → дизайнер пересдаёт → менеджер принимает. Журнал показывает все переходы.
- **AC-4:** Запрещённый dnd (например NEW→ACCEPTED) отбивается: карточка возвращается, toast с текстом бэка.
- **AC-5:** Все 4 состояния страницы наблюдаемы (empty — на чистом проекте; error — при отключённом бэке).
- **AC-6:** Пользователь без page-ключа не видит пункт меню и получает заглушку `PageGuard`.
