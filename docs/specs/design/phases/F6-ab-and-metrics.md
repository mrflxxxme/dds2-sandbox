## Goal

Замкнуть контур «задача → макет → АБ-тест → дельта конверсии» — то, ради чего модуль отличается от внешних трекеров (PRD).

## In scope

`backend/services/design/ab_bridge.py` · реализация `POST /design-tasks/{id}/ab-test` (объявлен в Ф2 как 501) · `tests/test_design_ab_bridge.py` · фронт: кнопка «Проверить тестом» на деталке (видимость по `permissions.can_create_ab_test`) + вкладка/панель метрик на странице списка (`GET /stats`).

## Out of scope

Автозапуск теста (создаётся draft — запускает человек на странице теста) · выбор campaign_id внутри модуля дизайна (передаётся параметром, выбор — на странице теста) → если `create_test` требует campaign_id обязательным, кнопка ведёт на предзаполненную форму создания теста (см. Hints) · автоподсказки «что переделать» → потом.

## Работы

### `ab_bridge.py`

```python
async def create_ab_test_from_task(db, project_id, task_id, user, payload) -> int  # ab_test_id
```

Ограничения (каждое — своя ошибка с человеческим текстом):
- задача в `ACCEPTED` (иначе 400 «Тест создаётся только по принятой задаче»);
- `nm_id` задачи заполнен (иначе 400 «Привяжите товар к задаче — тест сравнивает карточку конкретного артикула»);
- берётся ПОСЛЕДНЯЯ версия с `verdict=ACCEPTED`; из её файлов — только `mime_type LIKE 'image/%'` (иначе 400 «В принятой версии нет изображений»);
- вызовы строго через существующий сервис: `ab_photo_tests.create_test(db, project_id, nm_id=task.nm_id, ...)` затем `add_variant(...)` по каждому изображению — PIL-валидацию (≥700×900, ≤10 МБ, лимит 10) НЕ дублировать, транслировать её ошибки как есть;
- в `comment` теста — обратная ссылка `DES-N`;
- ответ `{ "ab_test_id": int }`; фронт редиректит на `/p/{slug}/ab-tests/{id}`.

### Метрики (фронт)

Панель над списком (или вкладка): 6 значений `GET /stats` за период (дефолт — последние 30 дней): доля в срок · среднее версий до приёмки · медиана цикла · без исполнителя >2 дней · доля аутсорса · доля задач с товаром. `formatNumber(x, 0)`/проценты; состояние «данных мало» при <5 принятых задач (PRD §10: первый месяц — точка отсчёта).

## AC

- **AC-1:** из принятой задачи с nm_id и версией из 2 png создаётся тест; `AbPhotoVariant` count == 2; в тесте корректный nm_id.
- **AC-2:** задача не в ACCEPTED → 400 с заданным текстом; без nm_id → 400; версия без изображений (только pdf) → 400.
- **AC-3:** невалидное изображение (меньше 700×900) — ошибка PIL-валидации донора транслируется, тест не создаётся наполовину (транзакция откатывается).
- **AC-4:** изоляция: task_id чужого проекта → 404.
- **AC-5:** `GET /stats` на фикстуре из 6 задач (2 в срок, 1 просрочена, 1 аутсорс, 2 без товара) возвращает ожидаемые значения (точный SQL-расчёт в тесте).
