## Как исполнять

1. Прочитать `CLAUDE.md` → [v1-CHARTER](../design/CHARTER.md) → [CHARTER.md](CHARTER.md) → [CONTRACT-V2.md](CONTRACT-V2.md) → [STATUS.md](STATUS.md) → phase-spec активной волны.
2. Ветка от свежего `sandbox/main`, одна на волну; цикл фазы — v1 §4 (Scope → Implement → Verify → Review → Close), TDD.
3. Порядок внутри волны: Model → Migration → Schema → Service → Router → Test → UI. Фан-аут на `tm-frontend` — только после мержа бэк-хребта волны.
4. Все волны трогают tripwire (`models/`, `migrations/`, `schemas/`, в волне C ещё `globals.css`) — правит только lead, волны B/C/D требуют подписи архитектора до мержа.
5. Закрытие волны — строка в STATUS (дата, commit-sha, evidence), owned-решения — в DECISIONS-LOG.
6. PR в `sandbox/main`, мерж по порядку A→B→C→D. В `origin` не пушится ничего (Р16 v1).

## Объём и порядок

| Волна | Слои | Миграции | Ревьюеры | Относительный объём |
|---|---|---|---|---|
| A | фронт + 1 аддитивный параметр ручки | нет | api · frontend · code | средний (6 правок, механических) |
| B | полный, узкий | `dsn04` (длина колонки) | database · api · code | малый |
| C | полный, широкий | `dsn05` (5 таблиц + сид) | database · security · api · frontend | большой |
| D | бэк-статистика + фронт-дашборд + XLSX | `dsn06` (1 таблица) | performance · api · code · frontend | большой |

Порядок задан ценой отката: сначала обратимый фронт, затем узкая миграция, затем новый слой
данных, затем аналитика поверх него. Заказчик видит первые правки после PR-A, не дожидаясь остального.
