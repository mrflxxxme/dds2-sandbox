## Goal

Метрика перестаёт мешать списку задач и превращается в отдельный разрез, из которого руководитель выгружает отчёт.

Таблица `design_dashboard_layouts` + миграция · три разреза статистики · ручки раскладки ·
XLSX-выгрузка · `design-tasks/analytics/page.tsx` + виджеты · таб «Аналитика» ·
удаление `StatsPanel` из списка. Контракт — CONTRACT-V2 §4.

## Работы

### 1. Раскладка на бэке (Р23)

**`design_dashboard_layouts`** — `TimestampMixin`
`id` · `project_id Integer FK projects.id` · `user_id Integer FK users.id` · `widgets JSONB NOT NULL`
`UniqueConstraint(project_id, user_id)` · индекс `(project_id, user_id)`.

`user_id` — тот же `users.id`, что в `assignee_user_id` задачи и в `user_id` строк `by-assignee`.
Значение берётся **из сессии**, никогда из тела запроса.

Таблица **бездетная** и намеренно выведена из-под паттерна `UniqueConstraint(id, project_id)`:
он нужен только родителям составных FK, а на эту раскладку никто не ссылается. Изоляция
обеспечивается парой `(project_id, user_id)` в каждом запросе. Это единственное исключение
в v2 — все остальные новые таблицы паттерн соблюдают.
`widgets` = `[{id, visible, order}]`; валидация состава — в схеме (известные id: `metrics`,
`by_assignee`, `funnel`, `by_attribute`), тексты ошибок — CONTRACT-V2 §4.
Миграция `dsn06_design_dashboard_layout.py`, `down_revision` = `dsn05` (волна C).
Ручки `GET/PUT /dashboard/layout`; `GET` без записи отдаёт дефолт с `is_default: true`.

### 2. Три разреза статистики

`GET /stats` (6 метрик PRD §10) — **семантику не менять**: `None` = «нет данных»,
окно режет по `accepted_at` для метрик приёмки и по `created_at` для входных.

| Ручка | Что считает | Донор / заметки |
|---|---|---|
| `GET /stats/by-assignee` | по исполнителю: принято, доля в срок, средний цикл, среднее версий до приёмки | `workload.py`: `ORDER BY … DESC` ДО `LIMIT`, сортировка по имени в Python; cap 200 |
| `GET /stats/funnel` | по 6 статусам доски: текущее число задач + среднее время в статусе | время — из `design_task_events` (append-only), **не** из `updated_at`: он затирается |
| `GET /stats/by-attribute` | распределение по значениям реквизитов и по меткам | требует волну C; задачи без значения → строка `«Без значения»`; архивные значения из выдачи не исключать (Р30) |

Каждый виджет — **один** запрос (AC-7). Просрочка везде = `due_date < сегодня` И активный статус;
задача без срока не просрочена — сквозное правило модуля, не переизобретать.

### 3. XLSX-выгрузка

`GET /stats/export.xlsx` — `StreamingResponse`, донор `problem_digest_xlsx.py`.
Состав листов, имя файла, заголовки и cap 5000 строк — **дословно CONTRACT-V2 §4**.
Доступ — всем с page-ключом (Р32), без `rate_limit_write` (read-ручка).
При усечении в «Сводке» появляется строка `«Показано 5000 из N задач — сузьте период»`.

### 4. Фронт: дашборд

`design-tasks/analytics/page.tsx`:
- шапка: `PeriodPicker mode="range"` (дефолт — последние 30 дней) · кнопка «Скачать отчёт» ·
  кнопка «Настроить виджеты»;
- сетка виджетов по сохранённой раскладке (`GET /dashboard/layout`);
- панель настройки: чекбокс вкл/выкл и drag для порядка, сохранение — `PUT /dashboard/layout`
  (оптимистично, на ошибке откат + toast текстом бэка);
- drag — нативный HTML5 (Р8 v1), новых зависимостей нет;
- каждый виджет сам обрабатывает loading/error/empty — падение одного не роняет страницу;
- у каждого виджета `InfoTip` (Р24) с объяснением формулы.

Виджеты v1: `metrics` (6 карточек-цифр, переезд `StatsPanel` вместе с логикой «данных мало») ·
`by_assignee` (таблица) · `funnel` (6 колонок с числом и средним временем) ·
`by_attribute` (распределения по реквизитам и меткам, цвета меток — из палитры Р26).

`DesignTabs`: вкладка «Аналитика» между «Загрузкой» и «Настройками».
`StatsPanel` из режима списка удаляется полностью.

## AC

- **AC-1:** `alembic upgrade head && downgrade -1 && upgrade head` — чисто, одна голова.
- **AC-2:** Вкладок 6 (Доска · Список · Календарь · Загрузка · Аналитика · Настройки); «Аналитика» открывается, все 4 виджета показывают данные за период.
- **AC-3:** Регресс семантики: `GET /stats?date_from=X` до и после волны D даёт **идентичный** ответ (снимок JSON до/после, эталон — ручка, а не удаляемая `StatsPanel`); шесть цифр виджета `metrics` совпадают с полями этого ответа поле-в-поле; в списке задач `StatsPanel` больше нет.
- **AC-4:** Выключенный виджет исчезает и **не запрашивает данные**; порядок после drag сохраняется на бэке и переживает перезагрузку и смену браузера; у другого пользователя своя раскладка; в другом проекте — своя.
- **AC-5:** `PUT /dashboard/layout` с неизвестным id → 400 «Неизвестный виджет: {id}», с дублем → 400 «Виджет повторяется: {id}».
- **AC-6:** «Скачать отчёт» отдаёт XLSX, который открывается openpyxl в самом тесте; проверяется поячеечно: лист «Сводка» повторяет значения ответов `/stats`, `/stats/by-assignee`, `/stats/funnel`, `/stats/by-attribute` за то же окно, лист «Задачи» — те же строки, что `GET /design-tasks` за период; при >5000 задач в «Сводке» есть строка «Показано 5000 из N задач — сузьте период»; мультизначные ячейки разделены запятой с пробелом.
- **AC-7:** Каждый виджет — ровно один запрос; число SQL-запросов каждого разреза не зависит от числа строк (тест-счётчик на 5 и на 50 исполнителях); `performance-optimizer` без BLOCK.
- **AC-8:** Поле `active` каждой строки `by-assignee` совпадает с числом активных задач того же исполнителя в ответе `GET /workload` за тот же момент (сценарий на 3 задачах, сверка по `user_id`).
- **AC-9:** Ошибка одного виджета (мок 500) не ломает остальные и не роняет страницу.
- **AC-10:** `viewer` с page-ключом видит вкладку и скачивает XLSX (Р32); вкладки «Настройки» у него нет.
- **AC-11:** `mypy`, `check_conventions.sh`, `tsc`, `vitest` — чисто.

## Hints

- `format()` по локальной дате, не `toISOString()` — вечером по МСК даёт минус сутки (грабли `StatsPanel`).
- Логика «данных мало» уже решена в v1: метрики приёмки `null` ровно при нулевой приёмке в окне; значения не прячем, а приглушаем + бейдж. Переносить как есть, не переизобретать.
- Числа — `formatNumber()`, проценты — хелпер `pct` из `StatsPanel`.
- openpyxl в deps (донор указан) — новых пакетов не заводить.
- `@cached` не добавлять (Р10 v1), несмотря на тяжесть разрезов: окно периода делает ключ кэша бесполезным.
- Cap и усечения показывать явно — «no silent caps».
- JSONB-колонка `widgets`: валидация только в Pydantic, в БД без CHECK — состав виджетов будет меняться чаще, чем схема.
