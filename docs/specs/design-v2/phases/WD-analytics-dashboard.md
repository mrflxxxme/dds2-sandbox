## Goal

Метрика перестаёт мешать списку задач и превращается в отдельный разрез, из которого можно выгрузить отчёт.

## In scope

`design-tasks/analytics/page.tsx` + `components/widgets/*` · раскладка в localStorage ·
расширение `services/design/stats.py` тремя разрезами · ручка выгрузки XLSX ·
удаление `StatsPanel` из списка · таб «Аналитика» в `DesignTabs` · амендмент CONTRACT.md.

## Out of scope

Конструктор произвольных виджетов (metabase-like) → потом (Р23) · бэк-персистенс раскладки → потом ·
PDF → потом · динамика по неделям → потом (не выбрана владельцем) · шаринг дашборда между пользователями → потом.

## Работы

### Бэк: три новых разреза

`GET /stats` уже отдаёт 6 метрик PRD §10 за окно — **семантику не менять**
(`None` = «нет данных», окно режет по `accepted_at`, `tracked_share` — по `created_at`).
Добавляются три ручки (или три секции одного ответа — решает исполнитель, но
**одним запросом на виджет**, не N):

| Разрез | Что считает | Заметки |
|---|---|---|
| `GET /stats/by-assignee` | по каждому исполнителю: принято, в срок, средний цикл, среднее версий до приёмки | донор — `workload.py`: `ORDER BY … DESC` ДО `LIMIT`, сортировка по имени в Python |
| `GET /stats/funnel` | текущее число задач в каждом статусе + среднее время пребывания | время — из `design_task_events` (append-only журнал уже есть): разница между соседними событиями задачи |
| `GET /stats/by-attribute` | распределение задач по значениям реквизитов (бренд/кабинет) и по меткам | требует волну C; фильтр окна — по `created_at` |

Все — `project_id`-scoped, с cap на строки, без `@cached` (Р10).
Пустой знаменатель → `None`, не `0` (сквозное правило модуля).

### Бэк: выгрузка XLSX

`GET /stats/export.xlsx?date_from&date_to&…фильтры` → `StreamingResponse`, донор —
`services/funnel/problem_digest_xlsx.py` (openpyxl уже в deps).
Два листа:
- **«Сводка»** — все виджеты за период: 6 метрик, разрез по исполнителям, воронка, разрез по реквизитам/меткам;
- **«Задачи»** — детальный список за период: номер, название, тип, сложность, срочно, исполнитель,
  автор, срок, статус, версий, метки, реквизиты, даты создания/приёмки.

Заголовки: `Content-Disposition: attachment; filename*=UTF-8''…` (паттерн модуля),
`X-Content-Type-Options: nosniff`. Read-ручка → без `rate_limit_write`, но с `require_role(page="design-tasks")`.
Cap: ≤5000 строк листа «Задачи», при усечении — явная строка-предупреждение в «Сводке»
(тихое усечение запрещено).

### Фронт: дашборд

`design-tasks/analytics/page.tsx`:
- шапка: `PeriodPicker` (волна A) + кнопка «Скачать отчёт» (XLSX) + кнопка «Настроить виджеты»;
- сетка виджетов; каждый — карточка с заголовком, тултипом-объяснением (Р24) и телом;
- **настройка**: панель со списком виджетов — чекбокс вкл/выкл и drag для порядка;
  раскладка (`{id, visible, order}[]`) хранится в `localStorage` под ключом с `project_id` и user;
  дефолтная раскладка — все виджеты видимы в порядке спеки;
- drag — нативный HTML5 (Р8 v1, прецеденты в репо), новых зависимостей нет.

Виджеты v1:
1. **6 метрик PRD §10** — карточки-цифры (переезд `StatsPanel`, включая логику «данных мало»);
2. **По исполнителям** — таблица/бары;
3. **Воронка статусов** — 6 колонок с числами и средним временем;
4. **По брендам/кабинетам и меткам** — распределение (требует волну C).

Каждый виджет отдельно обрабатывает loading/error/empty — падение одного не роняет страницу.

`DesignTabs`: пятая вкладка «Аналитика». `StatsPanel` из `ListView`/`page.tsx` удаляется
(в волне A он был опущен под таблицу — теперь уезжает совсем).

## AC

- **AC-1:** Вкладок 5; «Аналитика» открывается, все 4 виджета показывают данные за выбранный период.
- **AC-2:** Смена периода в `PeriodPicker` перезапрашивает все виджеты; цифры 6 метрик совпадают с тем, что показывал `StatsPanel` за то же окно (регресс семантики).
- **AC-3:** Выключенный виджет исчезает и не запрашивает данные; порядок после drag сохраняется между перезагрузками страницы; чужой проект — своя раскладка.
- **AC-4:** «Скачать отчёт» отдаёт XLSX, который открывается; лист «Сводка» сходится с экраном, «Задачи» — с фильтром списка за тот же период.
- **AC-5:** Разрез по исполнителям сходится с `GET /workload` по числу активных (перекрёстная проверка на 3 задачах).
- **AC-6:** Ошибка одного виджета (мок 500) не ломает остальные и не роняет страницу.
- **AC-7:** N+1 и тяжёлых запросов нет: `performance-optimizer` без BLOCK; каждый виджет — один запрос.
- **AC-8:** `mypy`, `check_conventions.sh`, `tsc`, `vitest` — чисто; в списке задач `StatsPanel` больше нет.

## Hints

- `format()` по локальной дате, не `toISOString()` — вечером по МСК даёт минус сутки (грабли `StatsPanel`).
- Просрочка в модуле везде = `due_date < сегодня` И активный статус; задача без срока не просрочена — не переизобретать в новых разрезах.
- Среднее время в статусе считать по `design_task_events`, а не по `updated_at` — журнал append-only, `updated_at` затирается.
- Числа на фронте — `formatNumber()`; проценты как в `StatsPanel` (`pct`).
- openpyxl уже в зависимостях (доноры перечислены) — новых пакетов не заводить.
- Cap и усечения логировать/показывать явно (правило «no silent caps»).
