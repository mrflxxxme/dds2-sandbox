## §3. Роадмап волн

```
A (UI-быстрые) ──► B (номер) ──► C (метки + реквизиты) ──► D (Аналитика)
   T1, frontend      T3, мини      T3, полный слой           T3, полный слой
```

| Волна | Название | Зависит | Tier | Исполнитель | Exit одной строкой |
|---|---|---|---|---|---|
| A | UI-быстрые: иконка, «Все бренды», тултипы, фильтры доски, рестайл календаря/пикеров | — | T1 | lead / tm-frontend | tsc+vitest зелёные; браузерный чек-лист A; PR-A замержен |
| B | Редактируемый номер заявки | A* | T3 | lead | миграция up/down/up; API-тесты уникальности/прав; PR-B |
| C | Цветные метки + справочник реквизитов | B | T3 | lead (хребет) + tm-frontend | миграции чисты; CRUD+фильтры работают E2E; PR-C |
| D | Вкладка «Аналитика» + XLSX | C | T3 | lead (бэк) + tm-frontend | виджеты сходятся с фактом; XLSX открывается; PR-D |

\* A и B технически независимы — B может стартовать до мержа PR-A, но PR'ы мержим по порядку.

Зависимость C→D содержательная: виджет «по брендам/меткам» требует сущностей волны C.
Фильтры доски по меткам/реквизитам (Р21) доезжают вторым заходом в волне C
(волна A ставит строку фильтров с тем, что уже есть: исполнитель/тип/срочно/поиск/статус).

## §4. Наследование v1

- **Цикл фазы** — v1 §4 (Scope → Implement → Verify → Review → Close), TDD, tier-ревью.
- **Инварианты** — v1 §6 все 10, плюс новые таблицы волны C обязаны повторить паттерн
  составного FK `(…, project_id)` c `UniqueConstraint(id, project_id)` родителя (изоляция БД, не кодом).
- **Растяжки** — v1 §7–§8; tripwire-пути (`migrations/**`, `backend/models/**`, `backend/schemas/**`,
  `rbac.py`, `cache.py`, `main.py`) правит только lead. Новые npm/pip-зависимости — эскалация
  (дашборд волны D строится на том, что уже в deps; dnd — нативный HTML5, прецедент Р8).
- **Evidence** — v1 §9: транскрипты test-runner, alembic up/down/up для B и C, браузерные чеки фронт-волн.
- **Кэш** — Р10 v1 действует: `@cached` не добавляем нигде, включая справочники и статистику.
- **CONTRACT.md v1 FROZEN** — новые ручки волн B–D оформляются **аддитивным** амендментом
  `docs/specs/design/CONTRACT.md` (раздел «V2 additions»), существующие тела/коды не меняются.

## §5. Что сознательно НЕ делаем в v2

Бэк-персистенс раскладки дашборда → потом (localStorage достаточно, Р23) ·
PDF-отчёты → потом · полный конструктор виджетов (metabase-like) → потом ·
удаление ручки `/all-projects` → потом (Р19) · история меток со счётчиком смен
(журнал и так пишет `DesignTaskEvent` — отдельного UI-счётчика «кругов» не строим,
раскрытие показывает текущие метки; вернуться, если Денис попросит явно) ·
глобальный (кросс-проектный) справочник реквизитов → потом · динамика по неделям
на дашборде → потом (не выбрана владельцем).
