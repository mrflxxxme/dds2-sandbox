# Как запустить систему у себя и проверить модуль «Дизайн карточек»

Инструкция с нуля: от чистого компьютера до работающей системы, в которой можно всё потыкать. Ничего программировать не нужно, команды копируются целиком.

Система поднимается локально, в изолированных контейнерах. Рабочая система и её данные при этом не затрагиваются — это отдельная копия только для вас.

---

## Часть 1. Один раз установить

Инструкция подходит и для Windows, и для macOS — команды одинаковые. Различия только в установке и в том, где открыть терминал; они отмечены ниже.

**Docker Desktop** — программа, которая запускает систему в контейнерах: https://www.docker.com/products/docker-desktop/

- **На macOS** выберите версию под ваш процессор. Посмотреть его: меню Apple (яблоко в левом верхнем углу) → «Об этом Mac». Если в строке «Чип» написано M1, M2, M3 или M4 — берите **Apple Silicon**, если Intel — версию для Intel. После установки перетащите Docker в «Программы» и запустите; при первом старте система попросит пароль — это нормально, Docker настраивает сетевые компоненты.
- **На Windows** просто запустите установщик и перезагрузитесь, если попросит.

После запуска дождитесь, пока значок кита в строке меню (macOS) или в трее (Windows) перестанет мигать — это значит, Docker готов.

**Проверьте память, выделенную Docker.** На macOS по умолчанию её часто мало, и сборка падает на середине. Откройте настройки Docker Desktop (шестерёнка) → **Resources** → ползунок **Memory** поставьте не меньше **4 ГБ**, лучше 6. Нажмите **Apply & Restart**. На Windows этот шаг обычно не нужен, но проверить не помешает.

**Git** — программа для скачивания кода.

- **На macOS** он, скорее всего, уже есть. Если нет — при первом же вызове система сама предложит установить «инструменты командной строки», согласитесь и подождите.
- **На Windows** скачайте с https://git-scm.com/downloads и установите со всеми настройками по умолчанию.

Больше ничего ставить не нужно: база данных, хранилище файлов и всё остальное поедут внутри контейнеров.

> На компьютерах Apple с чипами M1–M4 всё работает напрямую, без замедляющей эмуляции — все нужные образы собраны и под эти процессоры. Проверено.

## Часть 2. Скачать сборку

Откройте терминал:

- **macOS** — нажмите `Cmd + Пробел`, наберите «Терминал» и нажмите Enter.
- **Windows** — «Терминал» из меню «Пуск» либо Git Bash.

Команды ниже одинаковы для обеих систем. Выполняйте по очереди, копируя целиком:

```bash
git clone -b sandbox/full-build https://github.com/mrflxxxme/dds2-sandbox.git dds2-full
```

```bash
cd dds2-full
```

Первая команда скачивает сборку в папку `dds2-full`, вторая — переходит в неё. **Все следующие команды выполняются из этой папки.**

---

## Часть 3. Создать файл настроек

```bash
cp docs/specs/design/sandbox.env.example .env
```

Эта команда создаёт файл настроек с готовыми значениями: пароли для локальных контейнеров, отключённые связи с Wildberries и Telegram, разрешённая регистрация. Ничего в нём менять не нужно.

---

## Часть 4. Запустить

```bash
docker compose -p dds2-full -f docker-compose.yml -f docker-compose.sandbox.yml up -d --build
```

Первый запуск занимает **от 5 до 15 минут** — система собирается. В окне будет идти много текста, это нормально. Дождитесь возврата приглашения командной строки.

Проверьте, что всё поднялось:

```bash
docker compose -p dds2-full ps
```

Должно быть семь строк со словом `healthy`. Если у какой-то строки написано `starting` — подождите минуту и повторите: система накатывает базу данных.

---

## Часть 5. Войти в систему

Откройте в браузере: **http://127.0.0.1:13000**

Вы увидите страницу входа. Внизу есть ссылка **«Нет аккаунта? Зарегистрироваться»** — нажмите её (или сразу откройте http://127.0.0.1:13000/register).

Заполните форму: имя, фамилия, email, логин и пароль. Логин и пароль — любые, это ваша локальная копия. Нажмите **«Создать аккаунт»**.

Дальше система предложит создать проект — нажмите **«Создать первый проект»**, введите любое название, например «Проверка», и подтвердите.

Готово: вы владелец проекта, и вам сразу доступны все разделы.

---

## Часть 6. Найти модуль

В левом меню найдите группу **«Продажи»** и в ней пункт **«🎨 Дизайн карточек»**.

Откроется доска из шести столбцов: Новые заявки, Назначена, В работе, На проверке, Правки, Принято. Пока она пустая — это правильно.

---

## Часть 7. Пройти рабочий сценарий

Здесь вы за одного человека делаете то, что в жизни делают трое. Это нормально: вы владелец проекта, вам можно всё.

### Шаг 1. Создать заявку

Нажмите **«+ Новая заявка»**.

Заполните:
- **Название товара** — начните печатать, система предложит совпадения из справочника. В свежей системе справочник пуст, поэтому просто впишите текст, например «Кроссовки — главное фото».
- **Что нужно сделать** — пара предложений, не меньше десяти символов.
- **Ссылка на ТЗ** — любая ссылка, например `https://docs.google.com/spreadsheets/d/test`.
- **Срок сдачи** — выберите дату через неделю.
- Галочка **«Срочно»** — по желанию.

Обратите внимание: исполнителя здесь выбрать нельзя. Так и задумано — распределяет работу ведущий дизайнер.

Нажмите создать. Откроется карточка задачи с номером **DES-1** — нумерация сквозная внутри проекта.

### Шаг 2. Увидеть красную отметку

Вернитесь на доску. В столбце «Новые заявки» появилась карточка, а на ней **красная точка** — знак, что ведущий дизайнер её ещё не смотрел. Откройте задачу и вернитесь — точка исчезла.

### Шаг 3. Назначить исполнителя

На карточке задачи нажмите **«👤 Назначить»** и выберите себя. Задача переедет в столбец «Назначена».

### Шаг 4. Перетащить в работу

На доске **перетащите карточку мышью** из «Назначена» в «В работе». Она должна остаться там, а счётчики над столбцами — измениться.

Теперь попробуйте перетащить её сразу в «Принято». Карточка **вернётся на место**, и внизу появится подсказка с причиной. Так и должно быть: пропускать шаги нельзя.

### Шаг 5. Посмотреть календарь задачи

Откройте задачу и нажмите **«📅 Календарь задачи»**. Откроется окно с месяцем, где **полосой подсвечен период работы** — от постановки до срока, а сам срок выделен отдельно. Полистайте месяцы стрелками, вернитесь кнопкой.

То же окно открывается прямо с доски — значком календаря рядом со сроком на карточке.

### Шаг 6. Сдать работу

На карточке задачи нажмите **«Сдать работу»**, приложите любую картинку и напишите пару слов. Задача переедет в «На проверке», а в разделе версий появится «Версия 1».

### Шаг 7. Вернуть на доработку

Нажмите **«Вернуть»**. Попробуйте отправить с пустой причиной — кнопка не сработает, причина обязательна. Напишите причину и отправьте.

Задача уедет в «Правки», а на версии появится пометка «Возвращена» и ваш текст.

### Шаг 8. Пересдать и принять

Сдайте работу ещё раз — появится «Версия 2», задача снова на проверке. Теперь нажмите **«Принять»**.

Задача переедет в «Принято». Из этого состояния вернуть её нельзя — если понадобятся правки, заводится новая заявка.

### Шаг 9. Проверить журнал

Пролистайте карточку задачи вниз до раздела истории. Там должны быть **все переходы**: создание, назначение, в работу, на проверку, возврат с причиной, пересдача, приёмка — с вашим именем и временем. Эту историю нельзя стереть.

---

## Часть 8. Посмотреть остальные экраны

Над доской есть переключатель видов:

- **Список** — те же задачи таблицей, с фильтрами и поиском. Сверху — метрики за месяц.
- **Календарь** — общий месяц по всем задачам, с переключателем раскраски: по дизайнеру или по состоянию.
- **Загрузка** — таблица по исполнителям: сколько задач в работе, сколько просрочено. Отдельной строкой — незаназначенные.
- **Все бренды** — задачи из всех проектов, где вы состоите, с колонкой проекта.

Заведите ещё две-три заявки с разными сроками, чтобы эти экраны стало на чём смотреть. Поставьте одной срок во вчерашнем дне — она подсветится красным как просроченная, и в календаре тоже.

---

## Часть 9. Проверить, что защита работает

Система теперь проверяет права не только в интерфейсе, но и на сервере. Раньше можно было обойти запрет прямым обращением к API — теперь нет.

Проверить просто: в разделе **«Команда»** пригласите второго пользователя с ролью «Наблюдатель» и **не давайте** ему галочку «Дизайн карточек». Зарегистрируйтесь по приглашению в другом браузере (или в режиме инкогнито) — раздела в меню не будет, а прямая ссылка `/design-tasks` покажет заглушку «Нет доступа».

Ещё одно: попробуйте приложить к задаче файл `.svg` или `.html` — система его отклонит. Такие файлы могут содержать исполняемый код, поэтому теперь блокируются. Обычные картинки, PDF и архивы принимаются как раньше.

## Часть 10. Если что-то пошло не так

**Не открывается страница** — подождите минуту после запуска и обновите. Система накатывает базу данных при первом старте.

**Не загружаются файлы, пишет «Файловое хранилище недоступно»** — известная особенность чистой установки. Выполните две команды:

```bash
docker compose -p dds2-full exec -u root minio chown -R 100:101 /data
```
```bash
docker compose -p dds2-full restart minio
```

**Ошибка про POSTGRES_PASSWORD** — пропущена третья часть (файл настроек) или команда запущена не из папки `dds2-full`.

**`docker: command not found`** — Docker Desktop не запущен либо ещё не закончил старт. Запустите его и дождитесь, пока значок кита перестанет мигать. На macOS после самой первой установки может потребоваться заново открыть терминал.

**Сборка обрывается сама по себе, без внятной ошибки** — почти всегда не хватило памяти. Настройки Docker Desktop → Resources → Memory поставьте 6 ГБ, нажмите Apply & Restart и запустите команду из четвёртой части заново. Особенно актуально для macOS.

**macOS не пускает: «Docker невозможно открыть, так как разработчик не может быть проверен»** — откройте «Системные настройки» → «Конфиденциальность и безопасность», внизу будет строка про Docker с кнопкой «Открыть всё равно».

**Порт занят** — у вас уже что-то работает на этих портах. Откройте файл `docker-compose.sandbox.yml`, поменяйте числа `13000`, `18000`, `15434` на любые свободные и запустите заново.

**Хочу посмотреть, что происходит внутри:**

```bash
docker compose -p dds2-full logs backend --tail 50
```

## Часть 11. Выключить или удалить

Выключить, сохранив всё, что наделали:

```bash
docker compose -p dds2-full stop
```

Включить обратно:

```bash
docker compose -p dds2-full start
```

Удалить полностью вместе с данными:

```bash
docker compose -p dds2-full -f docker-compose.yml -f docker-compose.sandbox.yml down -v
```
