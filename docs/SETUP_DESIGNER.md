# DDS — бриф для дизайнера (работа через Claude Code)

> **Как пользоваться:** открой этот проект в **Claude Code**, приложи этот файл и напиши:
> «Прочитай SETUP_DESIGNER.md и работай по нему. Сначала подними окружение».
> Дальше просто описывай словами, что хочешь по дизайну — Claude реализует в коде.

---

## Кто ты и что делаем

Проект DDS — финансовое веб-приложение (Next.js 15 + React 19 фронт, FastAPI + PostgreSQL бэк).
Ты — **дизайнер**. Код руками не пишешь: дизайн-систему и вёрстку реализует **Claude по твоим описаниям**.
Твоя зона — **только фронт**, папка `frontend-react/`. Бэкенд не трогаем.

Пушить в основной репозиторий нельзя (доступ только на чтение) — работа отдаётся через **форк → Pull Request**.

---

## Требования на машине

- **Docker Desktop** (запущен) — всё крутится в контейнерах;
- **Git**.

Node.js и Python ставить **не надо**.

---

## Первый запуск (Claude выполняет один раз)

1. **Проверить форк:** `git remote -v`. `origin` должен быть форком дизайнера
   (`github.com/designnikitin/dds2`), а не `vladbydaev37/dds2`. Если это оригинал — предупредить, дальше не идти.
2. **Проверить Docker:** `docker info`. Не запущен — попросить запустить Docker Desktop.
3. **Создать `.env`:** `cp .env.example .env`, затем задать:
   - `SECRET_KEY` = случайная строка (`openssl rand -hex 32`);
   - `MINIO_ACCESS_KEY=minioadmin`
   - `MINIO_SECRET_KEY=minioadmin123`

   Ключи WB / Telegram / VTB **оставить пустыми** — для дизайна не нужны.
4. **Поднять контейнеры:** `docker compose up -d --build` (первый билд ~5–10 мин, дождаться).
   Docker сам подхватит `docker-compose.override.yml` — dev-режим с hot-reload фронта на :3000.
5. **Схема + демо-данные:** `make migrate` затем `make seed`.
6. **Проверить:** `make status` — все сервисы `Up`/healthy. Если упало — `make logs`, найти причину, починить.
7. Готово → сказать дизайнеру открыть **http://localhost:3000** и **войти под демо-аккаунтом
   `demo` / `demo1234`** — там уже есть данные (Demo Project: счета, транзакции за 30 дней).
   Свой аккаунт регистрировать НЕ нужно — новый пользователь получит пустой проект.

Правки фронта видны в браузере сразу (hot-reload), пересобирать ничего не надо.

## Как работаем над дизайном

- Дизайнер описывает словами или скидывает референс — **Claude реализует в коде**.
- **ОБЯЗАТЕЛЬНО** соблюдать правила из `.claude/rules/design.md` и `.claude/rules/frontend.md`
  (Claude Code видит их автоматически при правке `.tsx/.css`). Ключевое:
  - все цвета — через переменные `var(--color-*)`, **никаких hex** в компонентах;
  - все стили — в `globals.css` (для Telegram Mini App — `(tma)/tma/tma.css`), **никаких inline-стилей**;
  - скругления и отступы строго по сетке (отступы 4/8px; radius 8 / 12 / 14 / 20 / 24);
  - на каждой странице сохранять состояния **loading / error / empty / data**.
- Дизайн-система меняется **централизованно**: сначала токены/классы в `globals.css`,
  оттуда применяются везде — не хардкодить стили по месту.
- После каждого блока правок Claude говорит, что смотреть на http://localhost:3000.

**Где что лежит:**
- глобальные стили / токены темы — `frontend-react/src/app/globals.css`
- основной интерфейс — `frontend-react/src/app/(main)/`
- Telegram Mini App — `frontend-react/src/app/(tma)/`
- переиспользуемые компоненты — `frontend-react/src/`

---

## Границы (важно)

- **НЕ** менять логику API, типы `src/types/api.ts`, клиент `src/lib/api/` — только внешний вид.
- **НЕ** трогать папки `backend/`, `migrations/`, `scheduler/`.
- Если для дизайна реально нужно поменять данные или эндпоинт — Claude не делает это сам, а говорит дизайнеру.

---

## Как отдаём работу

Когда блок готов, Claude:
```bash
git checkout -b design/<название-задачи>
git add -A
git commit -m "design: краткое описание"
git push origin design/<название-задачи>
```
Затем на GitHub открывается **Pull Request** из этой ветки в `vladbydaev37/dds2`. Владелец проверит и вмержит.

> ⚠️ `make setup` (git-хуки) **не ставить** — pre-push гоняет тесты бэкенда и будет мешать.

## Шпаргалка

| Действие | Команда |
|---|---|
| Поднять всё | `docker compose up -d` |
| Остановить | `make stop` |
| Логи | `make logs` |
| Статус сервисов | `make status` |
| Пересобрать после `git pull` | `docker compose up -d --build` |

**Если сломалось** — показать Claude вывод `make logs` или текст ошибки. Частое:
пустой `.env` (см. шаг 3), занятый порт 3000/8000, забыли `make seed` (пустой экран без данных).
